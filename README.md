# 毎日1本 Webゲーム開発プロジェクト

## プロジェクトの目的

毎日1本のWebゲーム公開を目標に、企画、要件定義、設計、実装、テスト、独立レビュー、公開までを繰り返せる開発基盤を整備するプロジェクトです。ChatGPTを要件定義と独立レビューに、Codexを実装・自動テスト・修正に活用し、ゲーム制作を通じてWeb開発技術を段階的に習得します。公開の最終判断は人間が行います。

## 全体構成

| パス | 役割 |
| --- | --- |
| `requirements/` | ゲームの要件定義書、共通要件、受け入れ条件 |
| `templates/` | 要件定義、設計、テスト、レビュー、学習記録などのテンプレート |
| `games/` | ゲームごとの仕様、ソースコード、テスト、学習記録。`0001_slug` 形式で管理 |
| `shared/` | 複数ゲームで再利用するコード、スタイル、素材など |
| `reports/` | テスト結果、レビュー結果、進捗や公開記録などのレポート |
| `docs/` | GitHub Pagesで公開する成果物 |
| `AGENTS.md` | 人間・ChatGPT・Codexが従う開発・品質・公開ルール |

ゲーム固有のファイル構成は、初回ゲームの設計時にテンプレート化し、以後のゲームで改善しながら統一します。

## 開発から公開までのフロー

1. 学習テーマとゲーム案を決める。
2. ChatGPTで要件定義書と受け入れ条件を作成する。
3. 設計書を作成し、重要な設計変更は人間が承認する。
4. Codexが承認済みの要件・設計に沿って実装する。
5. PCとスマートフォンを対象に自動テストと操作性の確認を行う。
6. Codexが結果を報告し、必要に応じて原則最大5回の修正ループを行う。
7. 実装担当から独立したChatGPTが要件適合性、品質、回帰リスク、素材ライセンスをレビューする。
8. 人間が公開可否を承認する。
9. 明示的な指示に基づき、Pull Requestのマージと `docs/` からのGitHub Pages公開を行う。
10. ゲーム公開後、ChatGPTが原則としてキャラクター対話形式のnote用解説記事を作成する。記事にはゲーム概要、遊び方、攻略、制作技術、学習事項、ゲームURLを含める。
11. 実際のゲーム画面を使用したスクリーンショットと必要な図解・サムネイル画像を制作し、記事と実装済みゲームの整合性を確認したうえで、人間の承認後にnoteへ投稿する。記事原稿と画像の管理場所は、ゲーム別テンプレートの設計時に統一する。
12. 学習事項と改善点を記録し、次のゲームに反映する。

## GitブランチとPull Requestの運用方針

- `main` はレビュー済みかつ公開可能な状態を保つ。
- ゲームや管理作業ごとに作業ブランチを作成し、1つのPull Requestに目的の異なる変更を混在させない。
- Pull Requestには、関連する要件、変更概要、テスト結果、既知の問題、レビュー観点を記載する。
- 既存ゲームや共通資産に影響する変更では、回帰テスト結果を添付する。
- ChatGPTによる独立レビューと人間の承認を経てからマージする。
- Push、Pull Request作成、マージ、公開は、人間の明示的な指示を受けてから実施する。
- GitHub Actionsの成果物保存は必要最小限とし、大容量のテスト動画やスクリーンショットを無条件にアップロードしない。
- CI成果物の保存期間と容量を管理し、容量制限に達した場合は無理に再実行せず状況を報告する。

## 学習ロードマップとの関係

初期段階は、依存ライブラリを使わないHTML / CSS / JavaScriptを中心に、DOM操作、イベント処理、ゲームループ、状態管理、レスポンシブUI、テストの基礎を学びます。その後は、各ゲームの振り返りと学習計画に基づき、テスト自動化、ビルドツール、型システム、フレームワーク、バックエンド連携などを必要性のある段階で導入します。

新技術を導入したゲームでは、目的、設計判断、導入結果、理解できた点、今後の課題を学習記録に残します。技術導入そのものを目的にせず、既存ゲームの安定性と短い公開サイクルを維持します。

## 今後の環境構築予定

- 要件定義書、設計書、テスト計画、独立レビュー、学習記録のテンプレート整備
- ゲーム単位の標準ディレクトリ構成と命名規則の具体化
- JavaScriptの静的解析、フォーマット、単体テスト環境の選定
- Playwrightなどを用いたPC・スマートフォン向けE2Eテスト環境の検討
- `docs/` へ安全に公開成果物を生成する手順の整備
- GitHub Actionsによるテスト・品質確認の自動化検討
- GitHub Actions成果物の対象、保存期間、容量上限に関する運用設計
- GitHub Pagesの設定と公開前チェックリストの整備

導入するツールは学習計画とプロジェクトの必要性を確認し、承認を得たうえで段階的に追加します。
