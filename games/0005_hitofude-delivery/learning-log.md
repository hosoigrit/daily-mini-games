# Game #0005 学習記録

## 経路と巻き戻し

経路を唯一の正として持ち、回収済み荷物を経路から導出すると、戻る・リセット時に荷物フラグを個別同期する必要がなくなる。不正移動は新しい状態を作らず、得点もカウンターから導出することで二重減点を避けた。

## ヒント探索

固定模範経路の次セルを返す方式では、別解に入った正しいプレイヤーへ誤った案内をする。現在経路を訪問済みとして固定した探索により、別解からも正しい次の1マスを返せた。探索完了の`NO_SOLUTION`と、上限到達の`UNAVAILABLE`を分離したことが重要だった。

初期実装では同じヒント結果を同じrevisionへ二度適用できる余地があった。ヒント成功も状態変更として`inputRevision`を増やすことで、連打・重複結果の二重消費をコア層で防いだ。

## Pointer Events

入力側はPointer ID、イベント間のセル列化、中断だけを担当し、合法性はゲームコアへ集約した。同一行・列の高速移動は中間セルを補間できる。斜めのイベント飛びは勝手な曲がり角を作らず拒否することで、ショートカットを防いだ。

盤面だけへ`touch-action: none`を指定すると、盤面操作中のスクロール競合を抑えつつ、盤面外の通常スクロールを残せる。実際の指の挙動はiPhone等の実機受入で確認が必要。

## テストと修正

- 初回Node実行は42件中41件PASS、GC-10がFAIL。クリア後入力で内部メッセージだけ変化していた。
- 状態全体を不変に修正し、43件（RG-01追加後）を全PASS。

## 残る学習課題

- iPhone Safariでの`pointercancel`、ホームインジケーター、ツールバー、縦横回転の実測。
- 低性能端末でのヒント時間とUI停止感。Node実測値を実機値へ流用しない。
- 人間の試遊による6面の難易度・ヒント文言・誤操作の評価。

## 独立レビュー修正で得た学習

- APIメソッドの`getItem`／`setItem`だけでなく、`globalThis.localStorage`プロパティ取得自体が例外を投げる環境を考慮する必要がある。デフォルト引数は関数本体の`try/catch`より先に評価されるため、安全な取得は関数内部で行う。
- 「戻れる」と「前進できる」は別概念である。行き止まり判定では直前セルを除外し、早期ゴールも未回収荷物がある間は前進候補に含めない。
- メモリ継続できる保存障害でも、永続化失敗を結果画面で即時通知しないと利用者は記録が残ると誤認する。内部フォールバックとUI通知は両方必要。
- タイマー駆動UIは、単に`clearTimeout`するだけでなく世代番号を持たせると、画面切替後に到着した古いコールバックを確実に無効化できる。
