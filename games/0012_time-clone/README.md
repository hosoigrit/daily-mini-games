# 時間の分身

足取りを最大16枠記録し、その位置を再現する分身と協力してゴールまで進むパズルです。矢印キー、WASD、画面の方向ボタンで操作します。

## 仕様と検証

- [E1の設計・テスト原本](../../handoffs/game-0012/e1/)を基準にしています。初回検証値は500ms、FIFO容量2、単発遅延1000ms、累積遅延750msです。
- ゲームはHTML、CSS Grid、JavaScriptを使用します。ローカルHTTPサーバーでこのディレクトリを配信すると遊べます。
- Node.jsとPlaywrightで `npm test` を実行します。依存導入後、PlaywrightのChromiumをインストールするか、`GAME0012_CHROMIUM` でインストール済みChromiumを指定します。
- `GAME0012_TEST_REPORT` にJSONの出力先を渡すと、180ケースの結果と実施環境、対象SHA、主要ケースの実測ログを保存します。証跡採取時は対象コミットの作業ツリーをクリーンにしてください。
- `npm run verify:h01` で、製品コードを読み込まずに記録イベント補足を検算できます。補足のSHA-256は `b5db48b2f510c9754cd268c55ba7efb0eac5568899d06a54eacfc6e530fdd737` です。

## 開発記録

ドメイン関数は承認された順序で座標、スイッチ、解錠、扉、ゴールを更新します。時計、入力、保存、描画は外側に置き、テストも同じドメイン関数を使います。6ステージの地形と扉条件をE1のゴールデンデータから照合し、境界データはテストアダプターに限定しました。

T1-H01では記録CSVの状態差分から期待イベントを作成し、別の検算でゴールデンJSONの座標とマップから仕掛け状態を再計算しました。初回ブラウザ実行では狭幅テストがStage 6の開始行を取り違えていました。テスト側の開始座標を承認済みマップと照合し、タッチ入力後の座標とボタン寸法を再検証しました。

T2独立レビュー、T3の指定端末実機QA、T4の最適性証明は後続ゲートです。暫定星閾値の最適性は未証明です。保存初期化の比較と書き込みには別タブの同時更新が入り得るため、観測できた競合を中止し、読取不能時は初期化を拒否します。
