# Game #0008『3分探偵』v0.7.5 レビュー版（Draft PR・未公開）

「事件固定・真相変化型」の短編ロジック推理ゲーム。4事件×3真相=**12通り**を収録。ソース、HTML、CSS、ロジック、テスト、学習記録は全てこのゲーム専用ディレクトリ内に配置。

**未公開**：本ゲームは [GitHub Draft PR #14](https://github.com/hosoigrit/daily-mini-games/pull/14) の専用ブランチでレビュー中です。`main`へのマージ、GitHub Pagesへの公開、実機確認はいずれも未完了です。

## すぐに遊ぶ

ZIP内の `PLAY_OFFLINE.html` をブラウザで開いてください。単体HTMLにすべて埋め込み済み。インターネット接続や追加のソフトウェアは不要です。

ソース構成のまま遊ぶ場合はZIP展開先をターミナルで開いて `python -m http.server 8000` を実行し、`http://localhost:8000/games/0008_three-minute-detective/` を開きます。モジュール分割版はHTTP配信が前提です（`file://` からのモジュール読み込みは制限される場合があります）。

## 遊び方

1. 事件一覧から1事件を選択（4件とも開始時点から選択可能）。
2. 「事件の捜査を始める」で同じ事件の未解決真相からランダムに1つ出題。
3. 「事件の前提と証言」を確認し、根拠の証拠カードを2〜4枚選ぶ。
4. 推理ボードで犯人を1人選び、告発を確定。推理が論理条件を満たす場合に限り解決。
5. 失敗時は犯人を漏らさない共通メッセージ。ヒント2段階と、解説を見て終了する救済あり。
6. PC/スマホ両方から操作可能。スマホでは前提・証言のパネルを開閉できる。捜査を中断して別事件に戻れる。

## 得点・保存

- 初期1000点。根拠不足 -80、誤人物 -180、ヒント1段階 -200。制限時間なし。
- 正しい結論と立証条件を満たす証拠が必要。正しい別証拠と補強証拠を許容。
- 自力解決の初回記録・最高記録・事件ごとの解決済み真相はブラウザのローカルストレージに保存。
- 旧v0.5の同じoriginとストレージキーで保存されていた宝石事件の進捗は引き継げる設計。配布HTMLを別ファイルとして開いた場合の保存領域はブラウザによって異なり、共有保証はありません。

## 開発者向けテスト

`cd games/0008_three-minute-detective`

- `npm test`: Node組み込みのテスト。現在の件数と合否は実行時の結果を確認してください。
- `npm run validate`: 4事件・12真相の定義・解答可能性を検証（PASS）
- `python tests/browser-inline-smoke.py`: HTML/JSを単一ページに束ねてChromiumで操作検証する、代替テスト。実行にはPython PlaywrightとChromiumが必要。
- `python tests/browser-smoke.py`: ローカルHTTPで**実モジュール読み込み**と保存を確認するテスト。この実行環境では未実施。PCで実行要。

## 重要な制限

- 自動判定は「開示された共通前提」および「各証拠の事実タグ」に基づく閉世界モデル。自由記述の自然言語を自動論証するエンジンではない。
- 機器ログ・認証の完全性は事件の前提として明示しているが、自然さや難易度は未検証。実プレイヤーによる盲検テスト・第三者の公平性レビューが必要。
- 実機の Windows Chrome/Edge、Android Chrome、iPhone/iPad Safari ではまだ試験していない。
- 繰り返し性は12パターン分であり、全真相解決後の新規性は有限。
- 外部画像・音声・フォント・CDN・追加フレームワークは未使用。ゲームのグラフィックはHTML/CSSを用いて独自制作。

詳細は `TEST_REPORT.md`、`SCENARIO_REVIEW.md`、`MANUAL_QA_CHECKLIST.md` を参照してください。

## v0.7.3 IR-01 / IR-02 対応

- 真相開示済みバリエーションは `revealed` として保存し、初見・自力解決の実績に算入しません（同一セッションも含む）。他の未開示真相への自力解決は可能です。
- 既存v1保存データはそのまま読み込めますが、**旧版で既に見た真相**は記録されていなかったため、遡って判定することはできません。
- `proof-contracts.mjs` に独立の「必要な事実」「実行者を示す証拠」「実行時刻」を定義しました。`engine.mjs` は正解人物メタデータではなく、この証拠契約から推論し、答案のメタデータと契約の整合を検査します。
- 自動検証は人物名と時刻などの不整合を検出できますが、**物語全体の因果関係を機械的に証明するものではありません**。第三者の初見論理レビューは引き続き必須です。
- 現行の `STORAGE_KEY` は変えていません。利用不可の場合はそのセッション内のみ記録を保持し、次回アクセス後の保全は保証できません。


## v0.7.4 論証品質のガードレール・HTTPテスト修正

- IR-02: `evidence-propositions.mjs` に12真相の事実命題（種別・時刻・対象人物・肯定/否定・排他性）を独立管理。`approved-narratives.mjs` に事前レビューした事件前提・証拠文面を固定保存し、意図しない否定文・曖昧表現・別人物の追記・時刻・共通ルール・演出文章の変更を検出。本文変更時はレビューを通して承認済み原文を意図的に更新する。**自然言語を解析して犯人を自動証明する仕組みではない。**
- RIR-06: HTTP E2Eのドキュメントルートをリポジトリルートに修正し、index・JSモジュールがHTTP 200で取得できることを事前検査する。
- 否定表現、証拠文面変更、ルール・前提変更、人物・時刻変更に対する変異テストを追加。
- `approved-narratives.mjs` の原文と `evidence-propositions.mjs` の命題は、事件設計者以外の人間が推理の一意性・証拠と実行者の結びつきをレビューすることが最終条件。
