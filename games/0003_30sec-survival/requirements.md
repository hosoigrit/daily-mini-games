## 1. 背景・目的

1日で遊べるWebミニゲームを制作し、GitHub Pagesでの公開およびnoteでの開発解説につなげる「毎日1ゲーム制作PJ」の3本目として、リアルタイム回避アクションゲームを企画する。

Game #0001「ターゲットタップ」で扱ったタップ／タイマー処理、Game #0002「ひかりのパネル」で扱った配列／状態管理に続き、#0003では特に**Canvas、ゲームループ、経過時間ベースの移動、2次元ベクトル、衝突判定、タッチ入力、ゲーム状態管理**を学習対象とする。

### 1.1 成功の定義（暫定）

- 30秒間、隕石を予測しながら宇宙船を動かして回避する体験が成立する。
- PCとスマートフォンの双方で快適に移動できる。
- 衝突とライフ減少、クリア／失敗、星評価が矛盾なく動作する。
- ゲームロジックを描画から分離し、自動テストできる。
- 既存ゲーム・共通資産への無断変更なしに1ゲーム単位で実装・検証できる。

## 4. プレイ体験・基本ルール（案）

### 4.1 1プレイの流れ

1. タイトル画面でゲーム説明と開始ボタンを表示する。
2. 開始操作後、3秒のカウントダウンを表示する。カウントダウンは30秒の生存時間に含めない。
3. 宇宙船をフィールド中央に配置し、ライフ3でプレイを開始する。
4. 四辺のいずれかの画面外から、隕石が宇宙船の**出現時位置**を目標に直進する。
5. プレイヤーは下部固定ジョイスティックまたはWASD／方向キーで、宇宙船を2次元移動して回避する。マウスのジョイスティック操作はShouldとする。
6. 通常状態で接触した場合はライフを1減らし、衝突した隕石を消す。短い無敵時間を付与する。
7. ライフ0でゲームオーバー。ライフが残った状態で生存時間30秒に達するとクリア。
8. 結果画面にクリア／失敗、到達時間、残ライフ、クリア時の星評価を表示し、再挑戦できる。

### 4.2 クリア評価

| 結果 | 表示 | 補足 |
|---|---|---|
| 30秒生存・残ライフ3 | ★★★ | ノーダメージ |
| 30秒生存・残ライフ2 | ★★☆ | 被弾1回 |
| 30秒生存・残ライフ1 | ★☆☆ | 被弾2回 |
| 30秒未満でライフ0 | ゲームオーバー | 生存時間を表示、星は付与しない |

保存する個人記録は、同一ブラウザ内の「最高星評価」（0〜3）と「最長生存時間」（0〜30秒）の2項目を候補として採用する。星評価はクリア時のみ更新し、失敗時は最高星評価を更新しない。保存できない環境や破損値の場合にもゲームを継続できるものとする。ネットワーク共有やオンラインランキングは不要。

### 6.1 難易度・公平性に関する注意

- 到達時間の下限や同時数の制限は、不意打ちと極端な密集を減らす**簡易的なガードレール**である。これだけでは全ての局面で回避可能と証明できない。「理不尽な初期出現を減らす」と「全体の回避可能性を保証する」は別の要求である。
- 候補位置が不適切なら再抽選し、一定回数失敗した場合はその生成をスキップする。再抽選処理に無限ループを許容しない。
- 2個以上の隕石が同時に交差する場面、端に寄ったときの生成、狭い画面での可視性は重点試遊対象とする。
- 数値は自動テスト可能な設定データとして分離する。固定乱数による生成の再現、自動テストと人間の試遊の双方で検証する。
- 出現候補の適否判定に使う「到達時間」は生成時点で静止している宇宙船への仮想到達時間を意味し、移動する宇宙船との接触時刻を保証するものではない。

## 7. 画面・操作要件（案）

| 画面 | 主な表示項目 | 操作 |
|---|---|---|
| タイトル | タイトル、30秒生存の目的、操作説明、開始 | 開始ボタン |
| カウントダウン | 3→2→1、宇宙船の初期位置 | ゲーム移動入力は無効 |
| プレイ中 | 宇宙船、隕石、残り時間、ライフ、難易度 | ジョイスティック／キーボード |
| 自動一時停止 | 停止中の案内、再開ボタン。背景復帰で自動再開しない | 明示的再開 |
| クリア | CLEAR、星評価、残ライフ、記録、再挑戦 | 再挑戦 |
| ゲームオーバー | GAME OVER、生存時間、記録、再挑戦 | 再挑戦 |

- ジョイスティックはフィールド下部の**固定位置の専用操作領域**に置く。ゲーム領域の上に指が重なりにくく、隕石の視認性を保つ。外円・つまみの寸法とデッドゾーンは基本設計で確定する。
- PCでは縦長3:4のフィールドをページ中央に配置し、ゲーム領域と操作説明を明確にする。横画面でもゲームは利用可能で、画面回転を強制・禁止しない。
- 画面幅・高さに応じてフィールドを縮小し、座標・当たり判定・タッチ入力の対応を維持する。
- 操作中の画面スクロールを防ぐ処理はジョイスティックなど必要な操作領域に限定する。
- 画面上部のライフ／残り時間は操作領域や隕石の判別を妨げない。
- 背景はCanvas図形による星空、宇宙船は青系、隕石は橙系を基本候補とする。ライフはハートの形状でも表現し、色だけに依存しない。
- 被弾時は点滅を基本演出にする。機体の向き変更はShould。パーティクル・BGM・効果音は初回対象外。
- ジョイスティックへの押下・移動・離上・キャンセルは同一系列の入力として管理する。操作領域外へ指が出ても適切に操作終了・再開できること。

| AT-03 | 正規化 | 同時間・同入力強度での斜め移動距離が単軸移動距離を上回らない |
| AT-04 | 境界 | 全方向で宇宙船の判定範囲がフィールド外へ出ない |
| AT-05 | 隕石生成 | 4辺から生成可能で、生成時の宇宙船位置を目標方向にする |
| AT-06 | 非追尾 | 隕石生成後に宇宙船が移動しても、既存隕石の進行方向は変わらない |
| AT-07 | 生成制約 | 到達時間1.2秒未満の候補を棄却し、同時存在数の上限を超えず、再抽選失敗時も生成処理が停止せずにスキップできる |
| AT-08 | 衝突 | 非無敵時の1回の接触につきライフが1だけ減り、接触隕石が消える |
| AT-09 | 無敵 | 無敵時間中の追加衝突でライフが減らず、終了後は通常の被弾へ戻る |
| AT-10 | ゲームオーバー | ライフ0で停止し、クリア扱いにならない |
| AT-11 | クリア | 30秒到達時点でライフが残っていればクリアする |
| AT-12 | 星評価 | 残ライフ3／2／1に対して星3／2／1が対応する |
| AT-13 | リプレイ | ライフ・生存時間・隕石・無敵状態・難易度が初期化される |
| AT-14 | 記録 | 最高星評価・最長生存時間を更新・再読込でき、保存失敗・破損値でもプレイを継続できる |
| AT-15 | 一時停止 | 非表示になっても時計が進まず、復帰後の明示的再開までゲームが動かず突然被弾しない |
| AT-16 | タッチ | ジョイスティックを指で操作し、`pointercancel`等で入力が固着しない |
| AT-17 | レスポンシブ | 縦・横画面と代表的な画面サイズで固定ジョイスティックが見切れず、入力と描画位置が一致する |
| AT-18 | 実機 | Android Chrome／iPad Safariの確認に加え、iPhone Safari実機の結果を記録する |
| AT-19 | 公平性 | 各難易度で固定乱数を利用した100回以上の生成サンプルについて初期到達時間・同時数上限・無限再抽選防止を検証し、全30秒の複数回試遊で端付近・交差隕石の問題を記録する。**無条件の回避可能性保証ではない** |
| AT-20 | PCマウス（Should） | マウス操作を実装する場合はジョイスティックをドラッグして移動でき、キーボードとの併用で入力が固着しない |

これらはテスト計画の最終ケースではなく、要件受入のための候補。AT-19の「100回」は生成制約の機械的な検査件数であり、プレイヤーが全パターンで30秒生存できることを保証する基準ではない。試遊の回数・評価記録様式と不適切な難易度の判断方法はテスト計画で具体化する。

## 10. 初回制作の対象外

- 武器・射撃・敵の撃破・ボス戦
- プレイヤーを追尾し続ける隕石AI
- 複数種類の障害物、アイテム・パワーアップ、ステージ選択
- オンラインランキング、アカウント、クラウド同期
- BGM・効果音の本格実装、外部画像ライブラリや有償アセット
- 手動ポーズボタン（非表示時の自動停止・明示的再開は対象）
- 本格的なパーティクル・複雑な背景アニメーション
- 高度な物理演算、複雑な経路探索・絶対回避保証アルゴリズム
- インストール型アプリ化、サーバーバックエンド

## 11. 学習・開発運用要件

開発への着手は別途承認後のみとし、作業順は既存PJの標準フローを踏襲する。

1. 要件定義レビュー・承認
2. 基本設計書の作成・レビュー・承認
3. テスト計画・Codex実装依頼書の作成・承認
4. **明示的な実装許可を得てから**Codex実装と自動テスト
5. 実装担当とは独立したレビュー
6. PC／Android／iPad／iPhone実機確認
7. 明示的なPR・公開承認の後にGitHub Pagesへ反映
8. 実プレイ画像を用いたnote記事、学習ログへの展開

学習講座は「Canvas／ゲームループ」「ベクトル移動」「仮想ジョイスティック」「隕石生成と直進」「円形衝突と無敵時間」「状態管理・テスト」を柱とする。note記事の対話役は既存のハル（解説役）・ミナ（初心者役）を継続する。

### 12.1 正式承認前に確認する要点

1. OPEN-01〜09に対する上記の方針を、要件定義の前提としてよいか。
2. マウス操作・機体回転・ローカル保存などShould項目の優先度に異議がないか。
3. 公平性は「初期不意打ち防止の機械的制約＋複数回の試遊評価」とし、**全経路の回避可能性を数学的に保証しない**ことに異議がないか。
4. 数値はチューニング初期値であり、プレイテストの結果によって変更可能とする扱いに異議がないか。

### 12.2 要件承認後の設計持越し事項

ジョイスティックの寸法、半径、デッドゾーン、乱数生成の再試行上限、具体的な衝突半径、入力の優先順位、画面縮小時の最小サイズ、試遊記録様式は**基本設計・テスト計画で決める実装詳細**とする。要件定義の空白として放置せず、追跡対象として引き継ぐ。
