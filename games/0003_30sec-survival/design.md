## DD-01 全体方針とアーキテクチャ

- 仮想ゲーム座標360×480、縦長3:4の2D回避アクション。
- 宇宙船を8方向に操作し、画面の四辺から現れる1種類の隕石を回避。
- 隕石は**生成時の宇宙船位置へ直進**し、以後は追尾しない。
- 3ライフ開始、30秒生存でクリア。残ライフ3／2／1を星3／2／1に対応させる。
- スマホは固定ジョイスティック、PCはWASD／方向キーを必須。マウス操作はShould。

### 1.1 論理構成

~~~mermaid
flowchart TD
  UI["HTML UI / HUD / 操作領域"] --> IN["入力アダプター"]
  IN --> CORE["ゲームコア（状態・移動・衝突）"]
  CLOCK["ゲームループ / 時刻"] --> CORE
  RNG["乱数供給"] --> CORE
  CORE --> RENDER["Canvas描画"]
  CORE --> STORE["結果時のローカル保存"]
  CORE --> UI
~~~

**境界ルール：**ゲームコアはDOM、Canvas、localStorage、windowへ直接アクセスしない。描画・保存は結果を受け取って実行する。乱数・入力・時刻を外部から渡し、テスト時の再現性を確保する。

### 1.2 実装規模の方針

1. HTML／CSS／JavaScriptによる静的Web実行を基本とし、外部ランタイム依存を増やさない。
2. Mustを優先。Should（マウス・機体回転・保存表示）は必要なら段階調整する。
3. ゲームの時刻はゲームループで一元管理し、独立した複数のタイマーで進めない。
4. 既存ゲーム、shared配下、公開設定は本ゲームの設計対象外。

### 2.1 サイズ・表示ルール

- Canvasの**論理座標**は360×480を維持し、CSS表示サイズに応じて等比縮小する。縦・横画面とも中央表示し、端末の向きをロックしない。
- ジョイスティック用の領域高を**112 CSS px**とする初期案。画面が低いときは先にゲームCanvasを縮小し、操作領域の見切れを防ぐ。
- 描画内部の解像度はCSS寸法とdevicePixelRatioから設定し、論理座標に対応する変換をかける。画面回転・リサイズ時に再計算する。
- HUDやボタンをCanvasで描かずDOMを利用することで、操作性・文字の視認性を保つ。
- 操作領域だけタッチジェスチャー競合を防ぎ、ページ全域のスクロール・ピンチを一律禁止しない。
- PCは縦長フィールドを中央配置し、キーボード案内を表示する。

## DD-03 ゲーム状態遷移

~~~mermaid
stateDiagram-v2
  [*] --> TITLE
  TITLE --> COUNTDOWN: 開始
  COUNTDOWN --> PLAYING: 3秒経過
  PLAYING --> GAME_OVER: ライフ0
  PLAYING --> CLEARED: 30秒生存
  COUNTDOWN --> PAUSED: 非表示
  PLAYING --> PAUSED: 非表示
  PAUSED --> COUNTDOWN: 再開（元がCOUNTDOWN）
  PAUSED --> PLAYING: 再開（元がPLAYING）
  GAME_OVER --> COUNTDOWN: 再挑戦
  CLEARED --> COUNTDOWN: 再挑戦
~~~

| State | 主な処理 | 許可入力 |
|---|---|---|
| TITLE | 初期表示。時計・隕石は進めない | 開始 |
| COUNTDOWN | 3→2→1。ゲーム時計は進めない | 移動禁止 |
| PLAYING | 移動、生成、衝突、タイマー | 移動 |
| PAUSED | 状態と残時間を保持、更新停止 | 再開のみ |
| CLEARED | 星評価・記録表示 | 再挑戦 |
| GAME_OVER | 生存時間・記録表示、星なし | 再挑戦 |

- PAUSEDは停止前のCOUNTDOWNまたはPLAYINGを記憶する。再表示で自動再開しない。
- 同一更新でライフ0と30秒到達が重なる場合は**ライフ0を先に判定してGAME_OVER**。残ライフが1以上のときのみCLEARED。
- 再挑戦ではライフ、時間、宇宙船位置、隕石、入力、無敵、難易度を完全初期化し、ベスト記録だけ保持する。
- 終了画面・カウントダウン中に移動や隕石発生を進めない。

## DD-04 ゲームループ・時間モデル

### 4.1 固定ステップ方式（設計案）

- 描画契機はrequestAnimationFrameとする。
- ゲームロジックは**1/60秒の固定ステップ**で更新する。
- 描画時刻の差を累積し、累積値が1/60秒以上ならコア更新を進める。描画は各描画フレームで実行する。
- 処理落ちで異常に大きな経過差が来た場合、1描画で処理する差分を**最大0.25秒**相当に抑え、無制限の追いつき更新を避ける。
- この「30秒」は**ゲームが有効に進行したシミュレーション時間**。極端に遅い端末では現実の壁時計より長くなる可能性がある。NFR-04への適合を実機試験で検討する。
- PAUSEDからの再開では前回フレーム時刻と累積差分をリセットし、停止中の時間を計上しない。

| 項目 | ステップ |
|---|---:|
| カウントダウン3秒 | 180 |
| 生存30秒 | 1,800 |
| EASY：0〜10秒未満 | 0〜599 |
| NORMAL：10〜20秒未満 | 600〜1,199 |
| HARD：20〜30秒 | 1,200〜1,799 |
| 開始後の隕石生成なし1秒 | 60 |
| 被弾後の無敵0.8秒 | 48 |

表示残時間は **max(0, 30 - elapsedSteps/60)** を基準とする。

### 4.2 1ステップの処理順

1. PLAYINGであることを確認し、入力方向を取得。
2. 宇宙船移動とフィールド端制限。
3. 既存隕石を移動し、画面外へ抜けたものを削除。
4. 発生予定・同時数上限を確認し、新しい隕石生成を試みる。
5. 衝突検出、ライフ減少、隕石削除、無敵時間の扱い。
6. ライフ0ならGAME_OVER。それ以外は生存ステップを進め、1,800到達でCLEARED。
7. 結果への遷移時だけ記録保存を試みる。

無敵時間が0に達する境界ステップと、ライフ0／30秒の同時発生はテストで固定する。

## DD-05 宇宙船データと移動

| データ | 意味 | 初期案 |
|---|---|---|
| x, y | 中心の論理座標 | (180, 240) |
| hitRadius | 円形当たり判定半径 | 11 |
| speed | 速度（論理単位／秒） | 190 |
| lives | 残ライフ | 3 |
| invincibleSteps | 無敵残ステップ | 0 |
| heading | 機体の向き（Should） | 上向き |

入力方向を(dx,dy)とし、長さL = sqrt(dx²+dy²)とする。

- Lが0なら停止。Lが1を超えれば(dx/L,dy/L)に正規化し、斜め移動の速度増加を防ぐ。
- 1ステップの移動は方向ベクトル × 190/60。
- xを11〜349、yを11〜469の範囲へ制限し、当たり判定半径が場外に出ないようにする。
- 機体回転を採用する場合、方向からatan2で角度を算出。無入力時は直前の向きを維持する。

## DD-06 キーボード・ジョイスティック入力

### 6.1 PC（Must）

- W/A/S/Dと方向キー。keydown／keyupで押下集合を管理し、キーリピートで重複加算しない。
- 同軸の逆方向同時押しはその軸を0とする。操作中に限り方向キーのスクロールを防ぐ。
- 開始・再開時にフォーカスを適切に移し、非表示・フォーカス喪失・終了時に入力を解放する。

### 6.2 スマホ（Must）

- バトルの下の固定ジョイスティック。初期寸法：**外円直径96 CSS px、つまみ直径38 CSS px**。
- 中心Cと指位置Pの差分P-Cを最大可動量へ収め、-1〜1の2D入力ベクトルに変換する。
- デッドゾーンは**可動半径の約12%**を初期案とし、微小な指ぶれを停止扱いにする。
- pointerdownで有効pointerIdを保持、pointermoveで入力更新。pointerup、pointercancel、非表示、画面再配置では解除する。
- 主操作ポインター1本のみ採用。二本目の指が方向を奪わない。pointer captureは領域外移動でも固着させないために使用検討する。
- マウスでの同ジョイスティック操作はShould。操作を実装する場合は同一入力処理を使う。

### 6.3 同時入力

**初期案：**キーボードに非ゼロ方向があればキーボードを優先し、その他の場合にジョイスティック入力を使う。両者を単純加算しない。PAUSED・結果・再挑戦時は全入力を解除する。

## DD-07 隕石生成・難易度

| データ | 意味 | 初期案 |
|---|---|---|
| id | 一意な識別番号 | 連番 |
| x, y | 中心座標 | 四辺の外側 |
| vx, vy | 生成時に固定する速度ベクトル | 以後追尾しない |
| visualRadius | 見た目の半径 | 17 |
| hitRadius | 接触判定半径 | 14 |
| spawnedAtStep | 発生時の生存ステップ | 整数 |

### 7.1 生成の流れ

1. 上・下・左・右の4辺から乱数で1つ選択。
2. 選んだ辺に沿う座標を乱数で選び、辺から外側へ**22論理単位**離して生成候補を作る。
3. **その瞬間の宇宙船中心**をスナップショットとして保存する。
4. target-spawnを正規化し、ステージの隕石速度を掛けて(vx,vy)を固定する。
5. 以降は毎ステップ(vx/60,vy/60)ずつ直進。宇宙船の移動を追尾しない。
6. バトル領域から十分外側へ抜けた隕石を配列から除去。

### 7.2 生成ガードレール

出現点と宇宙船中心の距離D、当たり判定半径の和R、隕石速度vについて、

**概算の接触到達時間 = max(0, D-R)/v**

- 生成時点で宇宙船がその位置に静止していると仮定し、到達時間が**1.2秒未満なら候補却下**。
- 最大**10回**まで候補を再抽選し、不成立なら今回の生成をスキップ。無限ループを許さない。
- ステージの同時存在数の上限に達していた場合も生成をスキップ。後から一括発生させるキューは設けない。
- この制約は至近距離不意打ちの削減であり、複数隕石による**全局面の回避可能性は保証しない**。

### 7.3 3段階の難易度

| 経過 | 生成間隔 | 隕石速度 | 同時数上限 | 60Hz換算 |
|---|---:|---:|---:|---:|
| EASY：0〜10秒 | 1.4秒 | 100単位／秒 | 3 | 84ステップ |
| NORMAL：10〜20秒 | 1.1秒 | 120単位／秒 | 4 | 66ステップ |
| HARD：20〜30秒 | 0.9秒 | 140単位／秒 | 5 | 54ステップ |

最初の60ステップでは生成しない。その後の生成予定を単調増加するステップ数で管理し、難易度切替時にも生成待ちを大量に蓄積しない。

## DD-08 衝突・ライフ・無敵

宇宙船中心(xp,yp)、隕石中心(xm,ym)、半径rp,rmとすると、

**(xp-xm)² + (yp-ym)² <= (rp+rm)²** のとき接触。平方根は不要。

1. PLAYINGかつ無敵0で接触した場合、ライフを1減少し、接触した隕石を1体消す。
2. ライフが残れば無敵48ステップを付与し、宇宙船を点滅させる。
3. 無敵中の追加接触ではライフを減らさない。
4. 同じステップで複数接触しても、ライフ減少は**最大1**。
5. ライフ0ならGAME_OVERへ。残ライフ1以上で30秒に達したときだけCLEARED。

無敵47／48／49ステップ境界、同時接触、30秒同時発生を自動テスト対象にする。

## DD-10 一時停止・アプリ復帰

- documentが非表示になったとき、COUNTDOWN／PLAYINGならPAUSEDへ移行し停止前の状態を記録する。
- 停止時はキーボード集合・ジョイスティックのpointerId・入力ベクトルを解除する。
- 再表示後は自動で進めず、**再開ボタン**を表示する。
- 再開時に前回描画時刻とaccumulatorを初期化し、停止中の時間が一括計上されないようにする。
- COUNTDOWNから停止した場合は残カウントを維持して再開。タイトルや結果画面での非表示は不要なPAUSED遷移を起こさない。
- 手動ポーズボタンはMVP対象外。非表示の通知が発生しない特殊環境は実機確認へ引き継ぐ。

### 14.1 設計レビューで確認したい事項

1. 固定1/60秒のステップ方式でよいか。極端な遅延時は現実の30秒より長くなる可能性を許容できるか。
