## 1. 学習テーマ

- 主テーマ：ES Modules、二次元配列の純粋関数、明示的な画面状態遷移、`localStorage` の故障時フォールバック。
- 選定理由：Game #0001の単一ラウンド構成から、複数ステージ・永続進捗・境界値テストへ段階的に学習範囲を広げるため。
- 到達目標：DOMを状態の正本にせず、ゲームルール・固定データ・保存・表示を分離して検証できること。

## 2. 使用技術

| 技術 | 用途 | 使用経験 |
| --- | --- | --- |
| HTML5 | 5画面とネイティブボタンによる意味付け | 応用 |
| CSS Grid | 3×3／4×4盤面とレスポンシブ表示 | 応用 |
| JavaScript ES Modules | UI・盤面・ステージ・保存の責務分離 | 新規学習テーマ |
| `localStorage` | 解放済み最高ステージと自己ベスト | 応用 |
| `node:test` | 正常系・境界値・異常系の自動テスト | 応用 |

## 3. 新しく理解したこと

- `toggleCross` が入力盤面を変更せず新しい配列を返すと、角・辺・中央・2回反転の性質をDOMなしで検証できる。
- 画面状態を `TITLE / SELECT / PLAYING / CLEARED / ALL_CLEARED` に限定すると、クリア後の残留入力を状態ガードで拒否できる。
- 保存処理をクリア時だけに集約し、先にメモリ進捗を更新すると、保存禁止や容量不足でも同じページ内の進行を維持できる。
- ネイティブ`button`の`click`へ入力を統合すると、タッチ用とマウス用のハンドラ重複を避けられる。キーの自動反復だけを`keydown`で抑止した。
- ネイティブ`button`へ`gridcell`ロールを上書きすると、押下可能なコントロールとしての意味が弱くなる。レイアウトのCSS GridとARIAのgridパターンは別物として扱う。
- 静的データ検証をモジュール読込時の例外だけにすると、UIがエラー画面へ遷移する前に初期化が止まる。検証結果を値としてUIへ渡すと、異常時も利用者へ説明できる。
- 入力を検証する前の変換処理も例外源になる。`rows.map`の前に構造を安全に正規化し、正常値・異常値をどちらも「検証可能な値」として扱うことで、ERROR画面まで制御を渡せる。
- Gitを使えない変更範囲確認では、ハッシュの前後比較が有効。ただし、基準採取以前の未変更性までは証明できないため、「今回作業中は一致」と「過去工程は確認不可」を分けて報告する必要がある。
- ブラウザで動くことだけでなく、公開時に許可されたファイル集合だけで依存関係が閉じることも配布仕様の一部である。公開用6ファイルを隔離コピーし、静的参照と実ブラウザ読込の両方を検査すると、開発ディレクトリにだけ存在する補助モジュールへの依存を検出できる。

## 4. 実装上の課題

| 課題 | 原因・難しかった点 | 対応 | 結果 |
| --- | --- | --- | --- |
| 固定盤面の保護 | 画面側から配列を書き換えると再挑戦時に初期値が壊れる | ステージデータを凍結し、開始時に行ごと複製 | 自動テストで不変性を確認 |
| 保存値の整合性 | 型が正しくても解放段階とベスト手数が矛盾し得る | schema、範囲、必須済みステージをまとめて検証 | 不正値は安全な初期値へ復帰 |
| 色以外の状態表現 | 明暗だけでは点灯状態を判別しづらい | `ON/OFF`、`aria-pressed`、行列付きラベルを併用し、ネイティブbuttonの意味を維持 | 視覚・支援技術の両方へ情報を提供 |
| 実機証跡 | 「全端末PASS」の一括報告だけではケース・環境を追跡できない | 過去報告を消さず、正式状態を`MANUAL PENDING`へ分離し、ケース別テンプレートを作成 | 報告履歴と公開判断用証拠を混同しない |

## 5. 発生した不具合と解決方法

| 不具合 | 原因 | 解決方法 | 再発防止・テスト |
| --- | --- | --- | --- |
| ブラウザ試験スクリプトが初期化前のクラスを参照 | トップレベル実行がクラス宣言より先に進んだ | 実行本体を`run()`へまとめ、全宣言後に呼び出した | Chrome／Edge双方で再実行 |
| 合成`KeyboardEvent`と`button.click()`では実キー経路を再現できない | DOM内でイベントを作るだけではブラウザのネイティブ既定動作を検証できない | CDPの実入力経路からTab／Enter／Spaceと自動反復キーを送信 | Chrome／Edgeで開始・パネル操作・repeat抑止を再検証 |
| 静的ステージ不正時にエラー画面へ到達できない | モジュール評価中の例外で`game.js`自体が実行されない | 収集検証を例外なしの関数へ分離し、無効時は初期画面を`ERROR`にする | 不正コレクションのNodeテストと通常6面の回帰で確認 |
| `rows`欠落時は収集検証より前に例外になり得る | 固定定義の変換処理が`rows`の存在を前提としていた | `createStageCollection`で欠落・不正行を安全な無効値へ変換し、`resolveInitialScreen`へ渡す | ERR-01〜05をNodeとChrome／Edgeの実画面で確認 |
| TC-045の未変更証拠が弱い | Git禁止かつ過去工程開始前のハッシュ基準がない | 今回作業の前後スナップショットを採取し、比較範囲と限界を明示 | 今回中のGame 0001・shared・docs不変更をSHA-256で確認。過去全体は確認不可 |
| favicon未指定による404警告 | ブラウザが`favicon.ico`を自動要求 | 外部ファイル不要の空data faviconを指定 | Chrome／Edgeの警告・エラー0件を確認 |
| 公開用6ファイルだけでは起動不能になる構成 | RR-001対応で追加した`startup.mjs`を`game.js`が静的importし、承認済み配布構成へ含まれていなかった | `resolveInitialScreen`を`game-logic.mjs`へ、`setVisibleScreen`を`game.js`へ統合し、`startup.mjs`と専用テストを削除。検証範囲は配布構成テスト2件へ移管 | 6ファイル隔離環境のChrome／Edgeで正常起動、ERR-01〜04のERROR画面、ERR-05のTITLE、欠落リソース0件を確認 |

## 6. 技術選定の理由

| 選定内容 | 目的 | 採用理由 | 代替案 |
| --- | --- | --- | --- |
| ES Modules | 責務分離 | ビルド不要でブラウザとNodeの両方から読める | グローバル関数は依存関係が不明瞭になるため不採用 |
| 純粋な盤面関数 | 再現性の高いテスト | 入出力と不変性を直接比較できる | DOMクラスの直接更新は状態の正本が分散するため不採用 |
| Node標準テスト | 依存追加なしの検証 | 承認済み技術方針と既存環境に一致 | 外部テストライブラリは今回不採用 |
