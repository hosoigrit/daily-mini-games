## 5. 実装制約 [必須]

- HTML／CSS／JavaScriptのみ。ブラウザ標準APIを使い、初期段階は外部依存を追加しない。
- 画面遷移はREADY → PLAYING → RESULT → PLAYING。スタート前のカウントダウンなし。リプレイは新ラウンドへ直接移る。
- ターゲットは**同時に1個・直径64 CSS px**。命中まで表示維持、命中+1、ミス0、前座標との最低距離なし。HUD・領域外と重ならない。
- タブ非表示中も30秒の締切を維持。端末の前景復帰、画面回転、時刻境界、連打を考慮する。
- `localStorage`はゲーム0001の自己ベストのみ。ブラウザ／端末間同期なし。保存不能時も30秒完走・リプレイ可能にする。
- スマホでピンチズームを一律禁止せず、ゲーム操作中の意図しないスクロール・拡大を防ぐ。
- ターゲット操作はタッチ／マウス／Enter／Space。キーボード長押しの自動連打は重複加点させない。
- 秘密情報・個人情報はコード・テストデータ・ログに含めない。新規素材が必要な場合は著作権・ライセンスを確認する。
- **設計変更が必要な場合**：理由、影響FR/AC、代替案、推奨案を先に示し、重要な変更は人間承認まで保留する。
- 公開用`docs/`配置・Pages設定は今回の実装指示には含まない。

### 重点注意点（設計レビューに基づく事前確認）

1. **ネイティブボタンとキーボード**：ターゲットのEnter／Space押下を一度だけ採点し、ブラウザが合成する`click`と独自キー処理の二重加点が起こらないことを単体・ブラウザ操作の両方で確認する。
2. **残り時間の厳密性**：`Date.now()`による終了時刻との比較を、描画更新だけでなく採点直前にも実施。29.999秒と30.000秒の境界をテストする。
3. **円形の当たり判定**：64×64の描画枠からはみ出さず、表示された円のサイズとタップ・クリックできる領域が要件（AC-14）に一致することを実際のブラウザで確認する。
4. **小さい横向き画面**：568×320のCSS pxを含め、HUD・64pxターゲット・Safari UI・安全領域が干渉しないことを確認する。
5. **実機プレビューの提供方法**：iPadやAndroid実機からローカル検証環境へアクセスするための、安全かつ追加依存が少ないプレビュー手順を提案すること。**未承認の外部公開を行わない**。
