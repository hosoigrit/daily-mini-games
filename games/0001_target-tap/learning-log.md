## 1. 学習テーマ

- DOMイベントをマウス・タップ・キーボードで一貫して扱う。
- 描画頻度ではなく絶対締切を用いて30秒を判定する。
- 状態、DOM、保存、純粋ロジックを分離し、外部依存なしで境界値をテストする。

## 2. 使用技術

| 技術 | 用途 | 選定理由 |
| --- | --- | --- |
| HTML5 | 画面構造、ネイティブbutton、読み上げラベル | 意味構造と標準キーボード操作 |
| CSS3 | レスポンシブ、64px円形、セーフエリア、フォーカス | PC・モバイルを単一実装で対応 |
| JavaScript ES Modules | 状態遷移、入力、描画、保存、純粋ロジック | 責務分離とテスト容易性 |
| Node `node:test` | 30件の境界・状態・保存拒否テスト | 外部依存を追加しない |
| Chrome DevTools Protocol | 実ブラウザエンジンのスモーク検証 | 外部自動化ライブラリを追加しない |

## 3. 新しく理解・確認したこと

- `Date.now()`の締切を採点時・描画時・復帰時に再評価すると、背景タブで描画が止まっても期限後加点を防げる。
- タッチ専用イベントを追加せず`button`の`click`へ集約すると、互換クリックによる二重加点を避けやすい。
- ターゲットのEnter／Spaceはkeydownのrepeatを拒否し、対応するkeyupで1回だけ採点することで長押しを抑止できる。
- `localStorage`はアクセス自体が例外になる可能性があるため、読込・書込を別々に非致命化する必要がある。
- `window.localStorage`は`getItem()`より前のプロパティ取得時にも`SecurityError`を投げ得るため、プロパティ参照から例外境界に含める必要がある。
- 画面回転時は状態を作り直さず、現在座標が新しい境界外のときだけclampすれば得点・締切を維持できる。

## 4. 実装上の課題

| 課題 | 対応 | 結果 |
| --- | --- | --- |
| キーボード独自処理とネイティブclickの重複 | keydown既定動作を抑止し、keyup採点直後のdetail=0 clickだけ短時間抑止 | Chrome・Edgeで1押下1点 |
| 画面サイズ変更後の領域内保証 | 純粋な座標clampとresizeハンドラを分離 | 5サイズ×2ブラウザPASS |
| 保存拒否時の継続 | load/saveをtry/catchし、メモリ上のベストと非ブロッキング通知を維持 | 単体テストPASS |
| ブラウザ検証の外部依存回避 | Node標準WebSocketとCDPを使用 | Chrome／EdgeスモークPASS |

## 5. 発生した不具合と解決

ゲーム本体の不具合は検出されなかった。ブラウザテスト基盤で、プロファイルロック、クラス初期化順序、サンドボックス間のlocalhost到達、Edgeの小数測定誤差を修正した。詳細は`test-plan.md`のTH-01～04を参照。

## 6. 技術選定の理由

- 状態を`READY／PLAYING／RESULT`に限定し、仕様とテストの対応を単純化した。
- HUDとプレイ領域をレイアウトで分離し、ランダム座標計算からUI重複判定を排除した。
- 自己ベストキーにゲーム番号と版を含め、他ゲームの保存値と分離した。
- npmパッケージ、フレームワーク、ビルドツールは導入していない。

## 7. 次回への改善点

- 人間によるPC対話操作とAndroid／iPad／iPhone実機確認を実施し、自動結果との差を記録する。
- 独立レビューでアクセシビリティ、コントラスト、Safari固有挙動を確認する。
- 次ゲームでは、純粋ロジックの境界条件とブラウザ操作条件を設計段階で同じID体系にする。

## 8. 振り返り

外部依存なしでも、純粋ロジックとCDPを組み合わせることで境界値と実ブラウザエンジンの双方を検証できた。一方、ヘッドレス・エミュレーションは人間の実機操作を代替しないため、公開判定はHOLDのままとする。
