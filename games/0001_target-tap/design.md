## 1. 設計概要 [必須]

### 設計方針

1. **30秒の操作体験に集中**：タイトル → プレイ → 結果 → 新しいプレイ、の最小構成。開始前のカウントダウンはなし。
2. **ルールを固定**：ターゲットは同時に1個、直径64 CSS px。命中ごとに+1点、ミス0点、次の位置はランダム。ターゲットは命中までその場に残る。
3. **実経過時間を基準**：描画回数・タイマー実行回数で残り時間を減算せず、開始時に決めた終了時刻との比較で残り時間と時間切れを判定する。
4. **複数入力を統一**：マウスクリック、タップ、キーボードを1つの「有効命中」処理に集約し、ラウンド終了後や重複イベントの誤加点を防ぐ。
5. **PCとモバイルを同等に扱う**：Android Chrome、iPhone Safari、iPad Safariを考慮したレスポンシブ配置と、安全領域・縦横回転への追従を行う。
6. **自己ベストのみ保存**：今回のラウンド状態は永続化せず、ゲーム0001の自己ベストを同じブラウザの`localStorage`に保存する。失敗時もゲームは続行できる。
7. **小規模・テスト可能な構成**：外部ライブラリ・フレームワーク・サーバー通信・ビルドツールなし。時間・座標・保存値の判定は可能な限りDOM処理と分離する。

### 前提・制約

- 承認済みFR-01～FR-16、AC-01～AC-26、TBD-01～08、付随6事項を変更しない。
- インターネット公開は将来`docs/`への静的配置を想定する。**本段階で公開作業は行わない**。
- スコア公平性は端末をまたいで保証しない。音、オンラインランキング、SNS共有、難易度変更、コンボ、分析タグは初版の対象外。
- 保存値は同一オリジン・同一ブラウザ単位で管理する。プライベートブラウズやストレージ削除後の復元は保証しない。
- JavaScript無効時はプレイ不可であることを簡潔に示す方針とする。

## 2. システム構成 [必須]

ブラウザが静的HTML・CSS・JavaScriptを読込む。JavaScriptがゲーム状態をメモリで管理し、DOMの表示を切り替える。保存先はブラウザ内`localStorage`のみ。サーバーAPI・ログイン・外部送信はない。

| 構成要素 | 責務 | 入出力 |
| --- | --- | --- |
| `index.html` | タイトル・プレイ・結果の意味づけ、ボタン、スコア、時間、プレイ領域 | DOM要素、操作可能なラベル |
| `styles.css` | 配色、円形ターゲット、画面状態ごとの表示、フォーカス、縦横レスポンシブ | 画面サイズ／状態 → 表示 |
| `game.js`（UI・制御） | DOMイベント受付、状態遷移、表示更新、時刻確認、リサイズ、保存の呼出し | クリック／キー／時間／リサイズ → 状態・DOM |
| `game-logic.js`（純粋処理） | 残り時間計算、得点可否、位置の算出・補正、保存値検証 | 数値・状態・乱数 → 判定結果 |
| `localStorage` | ゲーム0001の自己ベスト1件の永続化 | 非負整数の文字列表現 ↔ `bestScore` |
| ブラウザの時計・描画機能 | 現在時刻・描画更新の起点を提供 | `Date.now()`、`requestAnimationFrame` |

**データの流れ**：ユーザー操作 → `game.js`の入力ガード → `game-logic.js`で判定 → 状態更新 → DOM再描画。ラウンド終了時、ベスト更新が必要なら`localStorage`へ保存。プレイ中の位置・得点・残り時間は保存しない。

## 3. 画面構成 [必須]

| 画面・領域 | 表示内容 | 主な操作 | PC／スマートフォン差分 |
| --- | --- | --- | --- |
| タイトル（READY） | ゲーム名、30秒・+1点・操作方法、スタートボタン | クリック／タップ／Enter／Spaceで開始 | 狭い幅では縦積み。タッチで押しやすい開始ボタン |
| プレイ中（PLAYING）：HUD | 「スコア：N」「残り時間：N秒」 | 読み取り専用 | スコアと時間を常時視認可能。横向き・小画面でもプレイ領域を圧迫しない配置 |
| プレイ中：プレイ領域 | 背景と**直径64 CSS pxの円形ターゲット1個** | ターゲットのクリック／タップ、フォーカス時Enter／Space | 画面の有効領域に合わせたサイズ。UIや安全領域と重ねない |
| 結果（RESULT） | 「終了」、今回スコア、自己ベスト、「もう一度」 | 再プレイを即時開始 | 縦積み表示。文字やボタンは切り欠き・ブラウザUIと重ならない |
| 保存エラー表示（必要時） | 「記録を保存できませんでした。このプレイは続けられます。」等 | 操作なし | 致命的ダイアログを表示せず、画面下部の短文などで補足 |

### 画面と操作の細則

- スタート／リプレイ／ターゲットは意味のある`button`要素で実現し、Tabでフォーカス可能にする。
- ターゲットは「ターゲットをタップ／クリック」のように読み上げ可能な名前を持つ。フォーカスは目に見える形で表示する。
- プレイ開始時はターゲットにフォーカスを移し、終了時は結果の「もう一度」へフォーカスを移す方針。タッチで不要なスクロールが起きないよう配慮する。
- スコア・残り時間は色だけに依存せず文字で表す。通常文字のコントラスト目標4.5:1以上。
- `viewport`指定で端末幅を基準とし、iPhoneのセーフエリアを`env(safe-area-inset-*)`で考慮する。`100dvh`と代替サイズを併用する設計候補とし、Safariの操作バー出没でも操作領域を確保する。
- 目標表示幅：320×568、375×667、390×844、568×320（横）、1280×720、1920×1080 CSS px。意図しない横スクロール、プレイ中の文字選択、ターゲットのダブルタップ拡大を防ぐ。ページ全体のピンチズームは一律禁止しない。
- スマートフォンのスコア・時間・ターゲットは同時に操作・視認可能とし、ボタン操作領域は44 CSS px以上を目安にする。ターゲット径だけは承認済み64 CSS pxを維持する。

## 4. 画面遷移 [必須]

```text
ページ読込／再読込
  └─ READY（タイトル、今回スコア0、タイマー停止、自己ベスト読込）
        └─ スタート → PLAYING（直ちに30秒開始）
                          └─ 30秒経過 → RESULT（結果・自己ベスト）
                                             └─ もう一度 → PLAYING（新ラウンド）
```

- `READY`からの開始は1回のみ受け付ける。同じ操作の重複発火による二重開始は無効。
- `PLAYING`からの終了条件は**30秒の期限到来のみ**。終了後はターゲットの入力を受け付けない。
- `RESULT`から「もう一度」を押すと`READY`には戻らず、そのまま新ラウンドを開始する。
- `PLAYING`中のページ再読み込みはブラウザの新規読込として`READY`へ戻る。終了前の今回スコアは復元しない。保存済み自己ベストは読み込む。
- ページが非表示になっても`PLAYING`のまま時間が経過する。再表示時に期限超過なら直ちに`RESULT`へ遷移する。
- `resize`／画面回転時に状態遷移は起こさない。スコアと終了時刻を維持し、はみ出したターゲットだけ座標補正する。

## 5. ゲーム状態管理 [必須]

| 状態・データ | 型・形式 | 初期値 | 更新契機 | 用途 |
| --- | --- | --- | --- | --- |
| `phase` | `'ready' | 'playing' | 'result'` | `'ready'` | 開始／時間切れ／リプレイ | 描画・入力の許可を制御 |
| `score` | 非負整数 | `0` | 開始・リプレイで0／有効命中で+1 | 今回の得点 |
| `bestScore` | 非負整数 | 保存値または`0` | 初回読込／ラウンド結果確定 | 結果と自己ベスト比較 |
| `startedAtMs` | Unix時刻ミリ秒／`null` | `null` | ラウンド開始 | 実経過30秒の起点 |
| `deadlineAtMs` | Unix時刻ミリ秒／`null` | `null` | 開始時に`startedAtMs + 30000` | 終了判定 |
| `remainingSec` | `0～30`の整数（表示用） | `30`（未開始画面では非表示） | 描画更新／期限判定 | 残り秒数表示 |
| `targetX`、`targetY` | プレイ領域左上からのCSS px | 未配置 | 開始／命中／必要なリサイズ補正 | ターゲット位置 |
| `roundId` | 非負整数 | `0` | ラウンド開始ごとに+1 | 前ラウンド由来の更新防止 |
| `animationFrameId` | ブラウザの描画予約IDまたは`null` | `null` | 描画予約・解除 | 多重更新の防止 |
| `pressedActivationKey` | `null | 'Enter' | 'Space'` | `null` | ターゲットへのkeydown／keyup／blur | キー長押しの連続得点防止 |
| `storageWritable` | 真偽値または未判定 | 未判定 | 読み書き時の成功／失敗 | 保存異常の非致命的処理 |

**不変条件**：

- `phase === 'playing'`のときだけターゲット1個を表示し、命中を採点する。
- `score`は各ラウンド開始時0、常に非負整数、1入力による増加は最大1。
- `deadlineAtMs`は当該ラウンド中に変更しない。再描画・画面回転・タブ移動は残り時間をリセットしない。
- `phase === 'result'`への遷移と自己ベスト確定はラウンドごとに1回だけ。
- `bestScore`は同一ページ内で非減少。保存値に問題がある場合は正常な`0`として扱う。

## 6. 主要な処理フロー [必須]

### PF-01 初期化（FR-01、FR-14、FR-15／AC-01、AC-22、AC-26）

1. 初期状態を`READY`、今回スコア0、タイマー非稼働で作成する。
2. `localStorage`の専用キー`daily-mini-games:0001:best-score:v1`から自己ベストを読み、非負の安全な整数でなければ0とする。
3. 保存領域にアクセスできない場合は0として続行し、通常の操作を妨げない。
4. タイトル・説明・スタートを表示し、ターゲットは表示しない。

### PF-02 ゲーム開始／リプレイ（FR-02、FR-11、FR-12、FR-14／AC-02、AC-09、AC-10）

1. `READY`のスタート、または`RESULT`の「もう一度」を受け付ける。
2. 入力を状態ガードで一度だけ処理し、`score=0`、`roundId`を更新、前ラウンドの描画予約を解除する。
3. 現在時刻`nowMs`を取得し、`deadlineAtMs = nowMs + 30000`を確定する。カウントダウンは入れない。
4. プレイ領域の実測幅・高さから初期ターゲット位置を求め、`PLAYING`へ遷移。表示は「スコア0／残り30秒／ターゲット1個」。
5. 描画更新のループを1本だけ開始する。ブラウザによるフレーム間隔は残り時間の根拠にしない。

### PF-03 ターゲット命中／ミス（FR-04～FR-08、FR-12、FR-13／AC-03～06、AC-10、AC-15、AC-20）

1. マウス・タップはターゲット`button`の`click`を単一の採点入口とする。`touchend`などから別に加点せず、タップと互換クリックの二重処理を避ける。
2. キーボードはターゲットのEnter／Spaceを操作する。対象キーの`keydown`で既定動作を抑制して押下状態を記録し、同じキーの`keyup`において**押下ごとに1回のみ**採点入口へ進める。長押しの`repeat`は無視し、フォーカス喪失時に押下状態を解除する。支援技術の`click`相当操作は引き続き受理する。
3. 採点入口で`PLAYING`かつ`Date.now() < deadlineAtMs`を確認する。時間切れなら終了処理へ移り、加点しない。
4. 有効命中なら`score += 1`、表示更新、プレイ領域内の次座標を抽選して同一ターゲットを移動する。前位置からの最低移動距離は設けない（同位置も可）。
5. 領域内の空白クリック／タップには採点リスナーを置かず、スコア・ターゲット位置を変えない。
6. 1つのDOMイベントを複数経路で採点しない。ラウンド・状態ガードにより開始前／終了後の入力も無効とする。

### PF-04 座標決定と画面回転（FR-04、FR-05、FR-16／AC-04、AC-13、AC-14、AC-25）

1. HUD・操作ボタンとプレイ領域をレイアウト上で分離する。座標系は**プレイ領域内部のみ**、原点は左上とする。
2. `targetSize = 64` CSS pxとし、`maxX = max(0, playfieldWidth - 64)`、`maxY = max(0, playfieldHeight - 64)`を求める。
3. ランダム配置は`x = random() * maxX`、`y = random() * maxY`（`0 ≤ random() < 1`）とする。境界値でも64×64のターゲット全体をプレイ領域内に収める。表示・当たり判定は同じ円の直径64 CSS px。
4. `resize`・向き変更でプレイ領域を再計測する。現在位置が新領域からはみ出す場合に限り`x/y`を新境界内へ補正し、スコア・終了時刻・ラウンドはそのまま維持する。
5. 64×64を置けない極端な表示領域では、プレイ領域の最小高さを優先して確保する。想定最小環境568×320（横）・320×568（縦）を実機・エミュレーションで必ず確認する。

### PF-05 タイマー／タブ非表示（FR-03、FR-09、FR-10、FR-12／AC-07、AC-08、AC-16）

1. 各描画時に`remainingMs = max(0, deadlineAtMs - Date.now())`を再計算する。
2. `remainingMs > 0`なら`remainingSec = ceil(remainingMs / 1000)`を表示する。開始直後は30、期限到来時は0。
3. `remainingMs === 0`なら、`roundId`と状態を確認し`endRound()`を一度だけ呼び、ターゲットを無効化して結果へ遷移する。
4. 非表示時は描画処理が停止・間引きされても**締切時刻を変更しない**。`visibilitychange`・`pageshow`・画面復帰時に期限を再評価し、30秒を過ぎていたら直ちに終了する。
5. 命中イベント内でも時刻を先に検証するため、描画が遅れた場合でも期限後の加点を防ぐ。
6. 時計の調整（利用者が端末時刻を変更）への厳密な耐性は初版対象外とし、通常の前景で±0.5秒の受け入れ基準を検証する。

### PF-06 終了・自己ベスト更新（FR-10、FR-14、FR-15／AC-08、AC-17、AC-22～24）

1. `PLAYING`かつ期限到来のときだけ一度`RESULT`へ遷移し、画面更新ループを解除する。
2. `score > bestScore`ならメモリ上の自己ベストを更新し、専用キーへ整数の文字列を保存する。同点・下回る場合は保存値を変更しない。
3. 保存に失敗しても結果画面に今回スコアとメモリ上のベストを表示し、再プレイを許可する。必要なら保存失敗を非ブロッキングで知らせる。
4. 結果画面には「もう一度」を表示。再プレイすると今回スコアは0に戻るが、メモリ内の自己ベストは維持する。

### PF-07 検証とリリース判定（AC-11～13、AC-18～21、AC-25）

1. 実装後、論理処理の単体テスト（境界時刻、ランダム位置、スコア、保存値、終了一回）とブラウザ手動操作を実施する。結果は`templates/test-plan-template.md`に沿って別途記録する。
2. Windows 11 Chrome／Edge、Android Chrome実機、iPad Safari実機の先行検証、端末サイズのエミュレーションを**区分して**記録する。
3. **公開前にiPhone Safari実機が必須**。`AC-19`～`AC-21`および関連項目についてChatGPTが手順・期待結果を提示し、人間が各IDに「確認できました／不具合あり／未確認」を報告する。
4. 人間が「確認できました」と報告した項目のみを「手動-実機／人間報告によるPASS」とする。iPad成功、エミュレーション成功、未報告をiPhone実機PASSに読み替えない。
5. 独立レビューと人間の公開承認を別途要求する。**要件・設計の承認だけで公開可能とは判定しない**。

## 8. 使用技術 [必須]

| 技術 | 用途 | 採用理由 | 新規導入 |
| --- | --- | --- | --- |
| HTML5 | ボタン、画面領域、説明、アクセシブルな文書構造 | ネイティブ操作を利用できる | いいえ |
| CSS3 | レスポンシブ、セーフエリア、フォーカス表示、円形ターゲット | 単一コードでPC・スマホをカバー | いいえ |
| JavaScript（ES Modules） | 状態・イベント・描画・タイマー・純粋ロジック | 責務分離とテスト容易性 | 設計上のモジュール構成のみ（外部依存なし） |
| `localStorage` | ブラウザ内の自己ベスト保存 | 承認済みTBD-04 B案を満たす | ブラウザ標準API |
