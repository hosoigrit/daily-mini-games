# Stage A-2a-R3 実機QAハーネス

専用入口はゲーム配下の qa/device-audio-clock/index.html。Node.js 26.13.1、npm 11.20.0、既存の依存と QA 専用 Vite 設定でビルドする。製品入口、本番ビルド、Playwright既定30ケース、ロックファイルはR2と同一。

- 音声アダプターと固定世代時計は src/infrastructure/web-audio.ts と src/domain/audio-clock.ts の実装を直接呼ぶ。試験曲と84秒fixtureも元の定義オブジェクトを直接参照する。
- 譜面・ゲーム入力は本ハーネスの対象外。ライブ時の判定は1本の100 ms監視から製品時計の observe に渡し、初回と20 msちょうどを含む同じ基準を適用する。UIの描画頻度、アプリが記録する丸め前診断値、統計は安全停止を決めない。
- 終了は一致する再生ID・時計世代のネイティブ通知と再生済みフレームを確認する。音声時計観測の量子化は Web Audio の既定1量子を終了証拠の分解能に使う。同期判定には作用しない。
- 冷生成は新しいアダプターで行う。製品がすでに使う OfflineAudioContext の返却バッファを観測し、レンダー完了時刻と全区間PCMを記録する。合成や波形処理を書き換えない。
- 最新試行の生成時間と状態、固定アンカー、時計世代、観測数、同期差、停止理由を表示する。同期差の図は測定済みデータだけを使い、診断表示を無効化できる。失敗・中止、確認できなかった解放も保持する。
- 各端末の条件は自己申告とビューポート観測に分ける。個人・端末識別子の収集はなく、試行IDはセッション内の乱数。出力はメモリから端末のダウンロード・コピーへ渡し、ブラウザ制約時は手動取得欄を使う。
- 実行済みと未実施を区別し、分位点は nearest rank。異なる条件の時間は個別集計。製品ゲート、物理試験、主観試聴の状態は変わらない。

実機手順は QA ディレクトリの device-test-plan.md、出力契約は同じディレクトリの evidence-schema.json。報告の実測サンプルはブラウザ自動化から得たもので、シミュレーションは TEST FIXTURE として管理する。
