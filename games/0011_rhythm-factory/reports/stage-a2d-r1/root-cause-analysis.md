# Stage A-2d-R1 原因切り分け

## 固定起点

A-2cのGitHub登録工程はユーザー承認でCLOSED。A-2d-R1の起点は `0d510986b9edfe2dbc33d9d1092b42bcc226ad2a`、tree `2dcc9d193b3eae27ffe317da65e126ecbb70d311`、独立レビュー済み実装は `165eccc8b223160088abd82ad78567b2f76e5208`。別リポジトリで前回bundleを復元し、32ファイル、承認済みパッチ、本番3アセットのSHA-256を照合した。原本30件、310 TC、581追跡行、125 AT、20 IF、11 QG、18 POCと既存ロックを確認した。

## 過去のブラウザ失敗

固定A-2dの統合16 FAILは、FirefoxのINITIALIZING停滞6、Chromium／WebKitのネイティブERR-006が9、本番版の制御入力遅着ERR-007が1。FirefoxやWebKitの挙動は固定済みの別音声ハーネスでも確認した。原因のブラウザ・音声経路・実行環境への帰属は、症状とエラーコードだけでは確定できない。

既存21 FAILはA-2aの独立音声ハーネス。Firefoxの有効化不能7、Chromium／WebKitの同期異常14。A-2cの16 FAILと照合し、名称まで一致した16件と、既存と同型のChromium変動5件を記録した。別のChromium再開例は同期安全停止の後に破棄済み音声への再操作でERR-004も発生。個別の試験名、ブラウザ、開発／本番、添付のSHA-256と再試験対応は引き渡し側 `evidence/failure-classification.json` を参照。過去のレポーターと添付は保存済みのまま維持した。

## 66.733msの再開起点ずれ

旧試験が、新世代の成立を最初に報告する画面診断の取得時刻と、停止位置Bの凍結値を同じ時点として引いた。旧ログの停止要求は操作の観測から推定perf 18,346.500ms、PAUSINGの観測18,347.200ms、PAUSEDの観測18,407.400ms。oは0、Bとbは4,164,400μs。設計上の停止整理後境界はb+1=4,164,401μs。旧ブラウザログに製品内部のコミット時刻と実際のa0・p0・asは未収録。再保持DOWNの受信18,562.300msから3秒後の21,562.300msが再開可能時刻だった。

最初の世代4診断21,565.500msから凍結値4,164.400msを引くと17,401.100ms。定常点21,575.600msと4,241.233msの差は17,334.367msで、同期した後続点も同じ起点だった。差は66.733ms。予定4,500,000μsの旧合成入力は付与時刻21,901.100ms、受信21,926.800ms、実判定4,566,733μs。固定コントローラー・譜面・保存経路で、同じ誤った起点の全129再開入力から15 PERFECT・67 GREAT・754,878点を再現。固定アンカーに基づく起点では82 PERFECT・100万点・最大コンボ82・ライフ200、保存1回だった。これは独立の決定的な前後比較。ブラウザ反復は別計上した。

## 73.933msと排他的な遅着境界

別の旧本番試行。制御試験が lane 3 UP に割り当てたPerformance時刻31,210.167msを、製品が31,284.100msに受信した。差は73.933ms。生成・dispatch時刻、DOMの元のEvent.timeStampは旧ログでは未観測。ネイティブの配送を73.933msとする証拠はない。この試行の旧起点のずれは78,600μsで、上の66,733μsとは別。予定12,800,000μsに対応する付与時刻を、固定時計で変換すると12,878,600μsだった。

最後の確定前サンプルjudge 12,930,633μsから50,000μsを引いたWは12,880,633μs。入力はこれより2,033μs古く、処理済み境界を越えたためERR-007で安全停止した。新しいテストは元のlane 3 DOWN／UP、世代3→4、停止整理とWで再現し、正式履歴の不変性を確認。別ケースでは、50.001msでもprocessedBeforeと同値なら受理し、50ms未満でも未処理入力が境界未満なら安全停止することを確認した。締め切り同値、旧世代の停止境界、重複ID、終端封印も実エンジンで検証した。

## 40.075msのネイティブ同期超過

旧最終本番単独試行は世代3、59点目、Performance 17,008.10000000149ms、丸め前の絶対差40.07499999552788ms。1点前との間隔116.700ms、先行58点の最大2.422167ms。PLAYING観測から5.866秒後にERR-006で安全停止し、save IDLE、音源とrAFが0、キャッシュ1。元レポーターには符号付き残差、a0・p0、観測contextTime・performanceTime、AudioContext状態、product playbackIdは未収録。旧値の閾値超過は確認でき、4つの元時刻からの独立再計算は新規観測で行う。比較版 `cde9c6a` の237点・最大2.492333ms・CLEAR/SAVEDはその版の結果として保全した。

R1の旧48試験の再試行は30 PASS・18 FAIL。旧FAILの4ケースがPASSへ変わり、既存のChromium POC-01が今回FAILになった。POC-01の3回の冷生成は4.9975、5.7000、5.4343秒で中央値5秒を超過。サンプル数、PCM、非有限値0、既存レンダー経路・試験・本番アセットの同一性は確認。旧A-2c中央値3.5109秒、旧A-2d中央値4.8872秒、R1の別系統の静穏計測中央値3.555秒。並行処理の寄与と、端末一般での再現性は未確定。最初のFAILは保全した。

## R1の実音声で取得できた生データ

固定Chromiumの単独実行12件。AG03とAG10がa0、p0、getOutputTimestampの対応する観測値から2,091点を照合し、受理2,086点・超過5点、判定・対応の不一致0点。成功試行の最大絶対差は10.602500ms。5点はいずれもnative state running、ERR-006 `clock.outOfSync`。

本番再保持1の最初の観測では、a0=2.926102833333333秒、p0=11,445.10000000149msから、contextTime=3.0463728333333338秒、performanceTime=11,605.40000000596msに進んだ。出力側Performanceの差160.300msに対してcontextTimeの差120.270ms、観測された現在音声時刻の差120ms、監視の入口間隔106.5ms。固定式で−40.030000msになる。履歴の40.075msは59点目で符号未取得。今回の近い量だけで同一根本原因とは決められない。

出力タイムスタンプの進み方が固定アンカーの予測と乖離する事象は確認。初回世代と再開世代の両方で出現し、同一AudioContextの観測対応で再計算が一致した。監視の遅れだけ、または旧世代混入だけで全事例は説明できない。ブラウザ、仮想音声経路、実行環境、製品統合への根本的な帰属は未確定。product playbackIdは既存経路未公開のため、テスト側のsourceIdを別に記録した。

7件はCLEAR/SAVED。5件はERROR/IDLEで保存処理の発生を観測せず、全12件で実音源の終了またはstop後のendedと、生成・再生・rAF・SFXが0を確認した。失敗試行の直接LocalStorage再読込は全譜面アーカイブに含まれない。連続操作では異常前の15件との同一性まで別途確認した。

旧Chromium POC-01の同一ハーネスを、R1実音声全譜面が終了してから静穏条件で1回だけ比較した。3.3582、3.5620、3.6443秒で中央値3.562秒、PASS。先に観測した5.434秒のFAILと併記し、条件差の関与は候補に留める。
