# Game #0006『交差点パニック』要件定義書

- 版: **v1.0-rc3**（承認候補・未承認）
- 文書ID: TP6-REQ
- 対象: `daily-mini-games` / Game #0006
- 目的: 1交差点の交通管制ゲームを通じ、AI駆動開発、有限状態マシン、決定論的シミュレーション、テストオラクル、独立レビューを学習する
- 制約: **ゲーム実装・GitHub変更を本書は許可しない**

## 1. 企画とユーザー体験
プレイヤーは十字交差点の東西・南北の信号を選択する。4方向から車両が直進してくる。限られた時間に渋滞を防ぎ、60秒生存と通過台数最大化を目指す。PC、Android、iPad、iPhone Safariを想定し、公開前のiPhone Safari実機確認を必須とする。

## 2. 固定ルール（企画上の非交渉条件）
| ID | 規則 | 受入条件 |
|---|---|---|
| RULE-01 | 十字交差点は **1か所** | 複数交差点を生成しない |
| RULE-02 | 北・南・東・西からの流入、全車直進 | 右左折・歩行者は対象外 |
| RULE-03 | 東西と南北が同時に青にならない | 信号FSM不変条件 |
| RULE-04 | 各流入方向は **8台まで待機可能** | 各待機数は0〜8 |
| RULE-05 | **同一方向の9台目が到着した瞬間、即GRIDLOCK** | 待機列に9台目を追加せず、猶予なし |
| RULE-06 | 黄・全赤中は新規通過しない | 対応するtickで通過イベント0件 |
| RULE-07 | 同tickでは、通過を新規到着より前に処理 | 8台→通過→到着なら8台で継続 |
| RULE-08 | 600tick到達時のCLEARを後続処理より優先 | tick600で信号操作・通過・発生なし |

## 3. 暫定BASEバランス設定（正式なゲーム難度は未検証）
| ID | パラメータ | 暫定値 |
|---|---|---|
| CFG-01 | ゲーム時間 | 600tick（60秒） |
| CFG-02 | 固定tick | 100ms |
| CFG-03 | 初期信号 | EW_GREEN、青開始tick0 |
| CFG-04 | 黄信号 | 10tick |
| CFG-05 | 全赤 | 5tick |
| CFG-06 | 青側各流入方向の通過機会 | 青開始12tick後から12tick周期、1方向最大1台/機会 |
| CFG-07 | 序盤発生 | tick13,26,...,195（15台） |
| CFG-08 | 中盤発生 | tick210,220,...,390（19台） |
| CFG-09 | 終盤発生 | tick408,416,...,592（24台） |
| CFG-10 | 流入方向確率 | 序盤N/S/E/W=25/25/25/25%、中盤15/15/35/35%、終盤35/35/15/15% |
| CFG-11 | 基本得点 | 通過1台につき10点 |

BASEの総発生予定は58台。ただし途中で敗北すれば未処理予定は発生しない。58台×10点=580点は単純な上限であり達成可能性は未証明。HARD-Aは終盤7tick（62台）、HARD-Bは黄10tick＋全赤10tick（58台）、EASY-Aは終盤9tick（56台）。比較設定のパラメータ変更でもRULE-01〜08を変更しない。

## 4. 機能要件（FR）
| ID | 要件 | 主要な受入条件 |
|---|---|---|
| FR-001 | 時間制御 | RUNNINGの600番目の更新でCLEAR。PAUSED中はtick進行なし |
| FR-002 | 信号切替 | EW_GREEN→EW_YELLOW→ALL_RED_TO_NS→NS_GREEN、逆方向も対称 |
| FR-003 | 操作制御 | 切替中の予約禁止、同tick最初の有効指示だけ受理、拒否理由記録 |
| FR-004 | 待機列 | 4方向別整数0〜8。合計による渋滞判定は禁止 |
| FR-005 | 車両発生 | seed＋設定＋生成器版で予定が完全再現。操作で変更されない |
| FR-006 | 車両通過 | 青方向の各流入から12tick周期で最大1台、待機0なら空振り |
| FR-007 | 渋滞終了 | 同一方向の8台待機中に次の1台が到着したら即GRIDLOCK |
| FR-008 | スコア | 通過済み台数×10、失敗・成功にかかわらず式は同一 |
| FR-009 | フェーズ別交通量 | 0–199、200–399、400–599の設定に従った生成予定 |
| FR-010 | 一時停止 | PAUSE優先、信号残時間・待機列・tickを保存し、明示再開 |
| FR-011 | 終了状態 | FINISHED後に結果や内部状態を変更しない。RETRYは新セッション |
| FR-012 | 再現性 | 同じルール版・seed・操作バッチログから状態とドメインイベントが一致 |
| FR-013 | 表示 | 現在信号・残り時間・スコア・4方向の待機数・切替中の残時間 |
| FR-014 | 操作性 | タッチ・マウス・キーボードで操作可。クリック連打でも二重切替なし |
| FR-015 | 結果画面 | CLEAR/GRIDLOCK、失敗方向、通過数、切替回数、生存時間を表示 |
| FR-016 | 最高記録 | 最高クリアスコアと最高挑戦スコアを区別し端末保存。表示レイアウトはP1 |
| FR-017 | 自動一時停止 | タブ非表示・顕著な描画停止でPAUSE、勝手に再開しない |
| FR-018 | 保存障害耐性 | 保存APIエラーでもゲーム自体は続行できる |
| FR-019 | 描画分離 | フレームレート、アニメ進行により論理結果が変化しない |
| FR-020 | 記録・追跡 | tick、操作順序、信号変化、通過・到着、終了原因を検証可能 |

## 5. 非機能要件（NFR）
| ID | 要件 |
|---|---|

| NFR-002 | BOTは交換可能で、Engineとはコマンド契約で接続する |

| NFR-004 | 同条件→同結果（決定論） |
| NFR-005 | 本番UIとテストが同じルール実装を使う |
| NFR-006 | 個人情報・秘密情報・認証情報を生成・保存・公開しない |
| NFR-007 | 設定、Engine、PRNG、BOT、イベントスキーマを識別できる |
| NFR-008 | 固定PRNG・統合テストオラクルと完全一致 |
| NFR-009 | 更新が失敗したとき、部分更新をコミットしない |

| NFR-011 | PAUSE/RESUME含む入力の処理境界と順序を再現できる |
| NFR-012 | 有効な人工SpawnScheduleで境界値テストができる |

## 6. UI・操作上の受入条件
- 画面: SCR-01 タイトル、SCR-02 プレイ、SCR-03 一時停止、SCR-04 結果。
- 待機数: 0〜4通常、5〜6注意、7〜8危険。色以外に数字・ラベルを併記する。
- 黄/全赤時の操作を後から予約しない。ユーザーには操作不可状態を分かる形で示す。
- プレイヤー向け説明では、BOT-05が参照する発生周期・フェーズ別方向確率を確認可能にする（メイン画面の常時表示は任意）。
- PC/Android/iPadの検証に加え、公開前はiPhone Safari実機で人間が操作する。

## 7. 記録・実験・承認境界
- ゲームの勝敗判定は「60秒クリア」を第一、通過数を第二の評価軸とする。
- バランス検証は500調整seed／300検証seed／200最終評価seedを使用。最終200seedは候補凍結後に初めて評価する。
- BOT評価は面白さの保証ではない。操作感・納得感を別途人間が判定する。
- GitHub Push、PR、マージ、Pages公開はそれぞれ人間の明示許可が必要。

## 8. 対象外・保留項目
- 対象外: 複数交差点、右左折、歩行者、オンラインランキング、マルチプレイ、AI API。

- P2: 効果音・装飾アニメーション・ログの永続保存範囲。
