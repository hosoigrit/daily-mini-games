# Game #0006 Phase E3-A 学習ログ

## 時間・入力・描画

RAFを時刻の受け口にし、SessionのelapsedTickを画面上の残り時間と結果の基準にした。fake clockで30/60/120 FPSの全Sessionを比較すると、同じtickへ入力を渡す限りイベント列と終端が一致した。背景停止と長いフレーム間隔では時間の蓄積を破棄することで、復帰直後の進行飛びを避けられた。

切替要求と制御要求を別の境界で扱う。切替は次tickまで保留できるが、一時停止時は同じSession境界に渡し、既存のPAUSE優先規則で破棄する。黄・全赤の間に入力を貯めると、青になった直後に意図しない切替を起こすため、入力時点で受け付けを止めた。

交差点はレスポンシブなSVG、操作と情報はHTMLで構成した。SVG内の車両と信号はエンジンの状態と通過イベントを読む。数字・テキストはHTMLに残し、画面読み上げには信号の状態変化と危険度の閾値変化を通知する。描画に外部フォントや画像を使わず、ビルド工程を設けずにサブパス上で配信できた。

## 監査と再現性

E1-L01では拒否後のゲーム状態と監査メタデータを独立に検証した。有効な拒否操作もシーケンスを消費することで、重複が後続のバッチ検査で検出される。E2-Cの監査には当時と同一SHAのSessionを一時ディレクトリへ配置し、凍結基準と現在のゲーム実行版を両方検証できるようにした。

ブラウザE2Eは通常経路での開始とRAF進行を確認した後、同じ画面にテスト専用の時刻とseedを与えた。これで待機時間と乱数による不安定さを避け、実際のボタン操作、結果、保存、スクリーンショットを同じ手順から取得できる。完走経路の入力tickは非holdoutの遊戯用seed 2001と既存BOT-04の単一トレースから得て、ブラウザテストでは固定のキー操作として再生した。

## 振り返り

ポート0のローカル配信と一時ブラウザプロファイルにより、E2Eをユーザーのブラウザ履歴や保存データから分離した。実機固有のセーフエリア、Safariの動作、読み上げ、タブ切替や中断操作の検証は、手順書に記録して実機確認に引き継ぐ。
