## 1. ゲーム概要・目的

天気に合わせてパンの販売価格と焼く個数を決め、5日間の累計利益を競う小さな経営ゲーム。**1プレイ約2〜4分**、時間制限はない。6種類の「一週間（5営業日）」を選べる。1週を終えたら同じ週に再挑戦して改善するか、別の週へ挑戦する。

### 遊びの核

- 単価を上げると客数が減る。製造しすぎると廃棄損、少なすぎると機会損失。
- 今日の天気と基礎客数、価格別の需要予報を見て2つの意思決定をする。
- 当日の実際の需要変動 `-2〜+2` は開店後までUIでは非表示。利益計算は再現可能な固定データを用いる。
- W01〜W06は同じルールの異なる5日構成で、毎回ランダムな天気生成はしない。

## 2. 対象ユーザー・環境

- PC／スマホで短時間に遊びたい日本語話者。予備知識不要。
- PC Chrome・Edge、Android Chrome、iPhone/iPad Safari。サポート対象は**公開時点で手動確認したバージョンを記録**する。
- 最小画面幅320 CSS px、横スクロールなし。マウス・タップ・キーボード操作で完結する。
- ゲーム内コインは架空通貨。個人情報・ログイン・課金・外部通信は扱わない。

## 3. スコープ・ルール

### 3.1 ゲームの基本数値（v0.2を基本として一部補正）

| 項目 | 値／規則 |
| --- | --- |
| 1プレイの日数 | 5日 |
| 初期資金 | 30コイン |
| 製造原価 | 1個につき2コイン |
| 販売価格 | 3／4／5コインから選択 |
| 製造数 | 0〜12の整数、かつ `2×製造数 <= 現在資金` |
| 各日の初期入力 | 価格4・製造数0 |
| 客一人が買う上限 | 1個 |
| 売れ残り | 当日廃棄、翌日に繰り越さない |
| 日次収支 | `販売数=min(製造数,実客数)`、`利益=価格×販売数−2×製造数` |
| 現在資金 | `当日開始時資金＋日次利益`。資金はマイナスにならない |
| 累計利益 | `最終資金−30`。マイナスもあり得る |
| 資金が2未満 | 製造0個で開店・翌日進行できる。途中ゲームオーバーなし |
| プレイ内容の乱数 | **なし**。同じ週と同じ選択なら同じ結果 |

### 3.2 天気別・価格別の来店人数ペナルティ

| 天気 | 価格3 | 価格4 | 価格5 |
| --- | ---: | ---: | ---: |
| はれ | 0 | 1 | 3 |
| くもり | 0 | 2 | 4 |
| あめ | 0 | 2 | **5** |

`実客数 = clamp(基礎客数＋需要変動−価格ペナルティ,0,12)`  
`予報下限 = clamp(基礎客数−2−価格ペナルティ,0,12)`  
`予報上限 = clamp(基礎客数＋2−価格ペナルティ,0,12)`。

`clamp(x,0,12)=max(0,min(x,12))`。すべて整数。予報は**今日の客数の可能範囲**であり、確約・確率分布・売上保証ではない。天気が「くもり」と「あめ」では価格5の減少幅のみ1人異なる（v0.4レビュー修正）。プレイヤーには価格3/4/5の予報を並べて比較できるようにする。

### 3.3 シナリオ仕様（v0.4で追加）

- 全6週：W01（はじめての一週間）、W02（あめの月曜日）、W03（晴れのお祭り）、W04（きまぐれ空）、W05（雨のち快晴）、W06（曇り空の商店街）。
- 各シナリオは日数5、日別の `weather`／`baseDemand`／`demandDelta` が決まっている。
- **正本データは** `06_scenario_matrix_v0.4.json` に収録。設計書内に別の独立した数値定義を作らず参照する。
- 最初にタイトルでW01が選択状態。その他の週も最初から選択可能で、解放条件は設けない。
- 週を選択した時点ではプレイを開始しない。「はじめる」を押すと日1のPLAN画面へ。プレイ中の**直接の**週変更は不可。
- PLANとDAY_RESULTから「途中でやめる」を選択できる。確認ダイアログで確定した場合のみ進行中の履歴・資金を破棄してTITLE（W01初期選択）へ戻る。**未完了週のベストは更新しない**。キャンセル時は完全に元の状態へ戻る。
- シナリオの名前は雰囲気づけのラベルであり、名前に対応する追加の経営効果はない。
- 開店前には**当日だけ**の天気・基礎客数・価格別予報を表示し、**当日の変動値と実需要、未来の日の情報は表示しない**。予報は「可能な客数の範囲（保証ではない）」と説明する。最終画面で少なくとも日ごとの実客数と日次利益を表示する。
- 焼く数が0個のときは、開店ボタンの直前に**「0個で開店すると売上0コインです。開店後は取り消せません」**と表示する。0個の開店は有効な選択であり、警告のために別確認操作を追加しない。
- 静的Webのプログラムソースを調べれば日別変動値を知り得る。機密性は保証しない。

### 3.4 勝敗・ランク（v0.4で変更）

スコアは最終累計利益（全5日の日利益合計）とする。週ごとに理論最大利益 `M` を用意し、ランクは次で決める。

```text
★1閾値 = ceil(M × 58 / 100)
★2閾値 = ceil(M × 75 / 100)
★3閾値 = ceil(M × 90 / 100)

利益が★3閾値以上：★3 大繁盛
そうでなく★2閾値以上：★2 上手に経営
そうでなく★1閾値以上：★1 クリア
それ以外：未達
```

| 週 | テーマ | 最大利益 M | ★1から | ★2から | ★3から | 参考方針利益 |
| --- | --- | ---: | ---: | ---: | ---: | ---: |
| W01 | はじめての一週間 | 60 | 35 | 45 | 54 | 49 |
| W02 | あめの月曜日 | 69 | 41 | 52 | 63 | 54 |
| W03 | 晴れのお祭り | 79 | 46 | 60 | 72 | 66 |
| W04 | きまぐれ空 | 66 | 39 | 50 | 60 | 42 |
| W05 | 雨のち快晴 | 67 | 39 | 51 | 61 | 48 |
| W06 | 曇り空の商店街 | 60 | 35 | 45 | 54 | 41 |

表の最終列「参考方針の利益」は設計検算値であり、ゲームUIには表示しない。最大利益Mも**タイトル画面では表示せず**、各週の最終評価基準（3値）はタイトルか開始画面の説明で確認できるようにする。

Mは資金制約を含む到達可能な理論最大値。

### 3.5 リプレイと記録

- FINAL画面に「同じ週に再挑戦」「別の週を選ぶ」を表示。
- 再挑戦では資金30・日1・価格4・製造0・履歴空に戻り、シナリオIDだけ維持。
- 別の週を選ぶ場合はTITLEへ戻り、新しい週を選択して「はじめる」で開始。
- 最高累計利益は**各シナリオにつき1件**、同じ端末の `localStorage` に保存。ベストの高い週が有利になる「全週共通ランキング」は作らない。
- 6週の「★3達成数」は6週のベスト利益を読むだけで表示してよい。未記録は未挑戦扱い。達成数を別キーで保持しない。
- 記録不能（容量、プライベートブラウズ制限等）ではその旨案内し、ゲーム自体は継続。プレイ途中の状態は保存しない。
- 最終画面では**今回利益**／**保存済み自己ベスト**／**保存状態**を区別する。保存先を読めない・書けないときは「新記録を保存しました」と表示しない。読込不能のキーは「記録を確認できません」、未登録のキーは「未挑戦」と区別する。
- 記録値が破損している場合は「記録が読み取れません（次回の完走結果で更新予定）」と説明してもよい。読み取り成功かつ破損確認済みなら完走時に妥当な新記録で上書き可能。読込APIが例外を返した場合は旧記録の有無が不明であるため、上書きによって過去のベストを失わないよう当該セッションでは保存しない。
- ブラウザ再読込でTITLEへ戻り、W01が初期選択。途中の履歴は復元しない。

| 分類 | 要件 |

| 性能 | 5日分の計算と画面更新はユーザーアクションに同期、ネットワーク待ちなし |

| 記録不正 | 保存値が欠落・不正・拒否でもゲーム継続。週ごとの独立性を確保 |
| 素材 | 初版はCSSと文字記号を基本とし、権利未確認の第三者素材を利用しない |
| 保守性 | コアは純粋関数、複数週の計算と期待値は自動検証可能 |
