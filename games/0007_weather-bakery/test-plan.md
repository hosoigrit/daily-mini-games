## 5. 表示・E2E・実機確認

- ビューポート：320 / 375 / 768 / 1280 CSS px。レイアウトで横スクロールを防ぐ（`overflow-x:hidden`で隠すだけの対策は不合格）。
- 操作：タイトルの6週を選択、価格3種類切替、製造0と最大個数、開店、5日終了、同週再挑戦、他週に切替。
- キーボード：Tab/Shift+Tab、ラジオの矢印、Enter/Space、見出しフォーカス、可視フォーカス。
- 画面読み上げ：晴れ/曇り/雨、星ランク、利益のマイナス、保存不可を**文字でも**伝達。
- スマホ：iPhone Safari、iPad Safari、Android Chrome。PC：Chrome、Edge。シミュレータ結果と実機操作を区別して報告する。
- 表示中断／再読込／ブラウザバック：意図しない二重計算が起きず、再読込後はTITLEへ戻る。
- 5日終了・週別ベスト・「同じ週」「別の週」の2ボタンが各実機で使える。
- **0個で開店する**：警告の文章をボタンより前に表示する。0個で実際に開店できることも検証。
- **途中でやめる**：PLANとDAY_RESULTで確認／キャンセルを操作でき、フォーカスが適切に戻る。中断後のベストは変化しない。
- **天気差**：雨で価格5ペナルティ5、曇りで4が予報と実需要の両方に反映される。
- **注意書き**：「一週間は5営業日」「予報は可能範囲で保証ではない」を画面で確認。
- **ストレージ異常**：「記録確認不可」「未挑戦」「保存失敗」の区別が視認できる。

## 6. バランス・UXの人間テスト（計画）

- 初見プレイヤーにW01と他週1つを遊んでもらい、操作説明なしで「天気予報」「販売価格」「製造数」「廃棄」の意味が伝わるかを確認。

- 計測例：クリア完了率、初回スコア／星ランク、2回目の改善、誤タップ、再挑戦意向（記録は個人情報を含めない）。
- UX合否閾値は実装後に被験者数・実測データがそろってから定める。推測でPASSを作らない。
