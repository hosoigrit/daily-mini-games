# Game #0007 E1 学習記録

## 設計判断

- 承認済みの要件・基本設計・テスト計画を資料ブランチの `acd02b73877533759dc9135ebb5a5b849c13e97e` から転記した。シナリオJSONも同じリビジョンからバイト単位でコピーし、テストの基準にした。
- 実行時は静的ESモジュールのカタログを使う。読み込み時に日付・型・範囲・週ID・最大利益・星基準を検証し、全データを凍結する。独立DPはテスト側で資金残高ごとの合法手を探索する。
- コアの状態と日次明細は凍結する。`dispatch(state, action)` は成功時に新しい状態を返す。拒否時は元の参照を返す。開店後は `DAY_RESULT` で再開店を拒否するため、呼び出し側は各操作の戻り値を同期的に最新状態として採用する。
- 製造数の資金制約は計画と取引確定時の資金で判定する。取引後は選択値と日次明細に確定した製造数を保持し、翌日の計画で価格4・製造0へ戻す。
- 計算関数は不正な引数を `RangeError`、カタログの検証は不正な設定を `TypeError` で通知する。依存パッケージは追加していない。

## 検証と振り返り

- `npm test` でNode標準ランナーを実行する。予報90件、取引1,170件、星境界36点をケースごとに検証する。
- 理論最大利益の検算は、各日開始時の到達可能な資金ごとに合法手を列挙する。最大値だけでなくDPの経路と資料05の経路をコアで再生し、金額・在庫・履歴を突き合わせる。
- W02の合法経路で所持金0と1を作り、0個開店で5日間を完走できることを確認した。計算単体テストの組み合わせは、状態遷移でその資金にたどり着けるかとは独立に検証している。

## E2への引き継ぎ

- `createGameState()` で初期化し、操作はコアへ渡す。結果表示は `dailyResult` と `history` を参照し、評価は `rankForProfit(scenarioId, cash - INITIAL_CASH)` を呼ぶ。
- 計画画面で参照する情報は当日の天気・基礎客数・価格別の `forecastDemand` に絞る。0個警告と中断ダイアログの表示・フォーカス制御は基本設計に従う。
- 週別ベストは `SHOW_FINAL` が受理され初めてFINALに入った時だけ更新する設計。保存失敗時の表示、再読込、ブラウザ操作、実機での操作性は後続工程で検証する。

## E2 UI・操作・保存

- 画面遷移では見出しにフォーカスし、価格や個数の変更後は操作したコントロールに戻す。中断はネイティブのモーダルダイアログを使い、Escapeと「続ける」は中断ボタンへ戻す。
- 営業の確定は `OPEN_SHOP` のディスパッチに集約する。戻り値を同期的に採用し、日次結果と星評価にコアの値を使う。累計利益の算出はコアに参照用の `totalProfit` を追加した。
- 週別の値は `rules-v3` を含むキーで管理する。対象週の読込例外をページ内で保持し、同じページを開いている間はその週を上書きしない。書込失敗後も、確認済みの以前の値を表示できる。
- 暖色の紙面とCSSで描いた店先を使い、週カードは狭い画面で1列にする。画像・音声・フォントの外部素材や実行時依存は追加しなかった。
- E3では対象ブラウザでの正式なE2E、実機での操作と読み上げ、既存ゲームの総合回帰を確認する。
