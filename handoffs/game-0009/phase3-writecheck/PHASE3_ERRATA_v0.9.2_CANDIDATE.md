# Game #0009『3手の勇者』Phase 3 保存確認不能時の設計補足 v0.9.2（承認候補）

作成日: 2026-11-23
状態: **未承認**。承認前に実装再開・GitHub書込みを許可しない。
対象: `hosoigrit/daily-mini-games` / Phase 3保存・復元機能

## 1. 背景・適用範囲

Codex Cloudによるv0.9.1受領確認で、`localStorage.setItem()` が正常終了した後、確認用`getItem()`が失敗するケースが不明確と判明した。本補足は保存結果確認に限った安全性ルールを加える。

- v0.9戦闘ルール、16ステージ、凍結済みPhase 1/2の22ファイルを変更しない。
- v0.9.1で確定した`clearCount`不使用、旧v1の明示移行、破損データ保護を維持する。
- 補助ケースE3-07の「元データ不変」は、**書き込み前に停止し無書込みであることが確認できた経路**に限定する。
- `setItem`が正常終了した後の`getItem`失敗には「無変更」を期待しない。既に反映済みの可能性がある。
- 未承認のままGitHubへの登録・Phase 3再開をしない。

## 2. 保存結果状態の契約

| 状態 | 意味 | UI/APIに提供する情報 |
|---|---|---|
| `saved` | 書込み後の読み戻しで期待するレコード（またはそれ以上の単調な記録）を確認した | 保存確認済み |
| `not_saved` | 書込み前に停止し、該当操作による変更が起きていないことを確認できる | 未保存・原因 |
| `unverified` | 書込みが正常終了したが、その後の読み戻し・検証が完了できない | 保存された可能性あり・未確認 |
| `blocked` | 読み込んだデータが不正、未知の形式、指紋衝突などで安全な更新ができない | 永続化停止・元データ保護 |

`setItem`が正常終了したことだけをもって `saved` を返してはならない。
一方、読み戻し失敗後に「保存されていない」「元データ不変」と断言してはならない。

## 3. `unverified` 発生時の厳密な振る舞い

1. `setItem`正常終了後、`getItem`例外・読み戻し不能となった場合、当該操作の状態を`unverified`にする。
2. 安全性を判断できるまでは、同じ保存キーへの**盲目的な再書込み・自動ロールバック・既存キー削除を禁止**する。
3. 当該試行の保存要求（ルール指紋、ステージID、獲得星、ノーヒント星）をセッションメモリ中に保留する。画面向けAPIには保存未確認の状態を返す。ページ終了後の復元を保証しない。
4. 次の再確認時はWeb Locksを取得してから、最新のv2データを読み出し、スキーマ、revision、ルール指紋の整合性を検査する。
5. 最新データが当該保存要求を満たしていれば、**追加書込み・revision加算なし**で`saved`を確定する。確認は要求した成果が維持されているかで行い、単なる生バイト一致に限定しない。
6. 最新データが正常だが要求結果未反映なら、最新記録との `maxStars` / `bestNoHintStars` の単調マージを行い、必要な場合のみ書込み、読み戻しで検証する。
7. 読み込みが再度失敗した場合は`unverified`を維持。未知スキーマ、破損、指紋衝突の場合は`blocked`とし、元データを上書きしない。
8. 復旧中に別タブが進捗を保存していても、ロック下で最新状態を再読込し、他ステージや旧ルールの記録を失わない。
9. 設定保存は進捗と別キー・別契約で管理する。設定のlast-write-winsは許容されるが、確認不能を成功と偽らない。
10. UIはPhase 4で実装する。本Phase 3では状態を返すAPIおよび依存注入モックのテストだけを作る。

**原則**: 不明な永続化結果は、成功と失敗のどちらにも確定させず、安全な照合ができるまで保留する。

## 4. E3-07の適用範囲

- Web Locks未取得、ロック待ちで中止、バックアップ取得前の失敗、検証時の拒否など、**永続化書込みが実行されていない場合**は「元データ不変」を期待する。
- `setItem`の**正常終了後**の確認不能はE3-07から除外し、E3-09〜E3-13で扱う。
- `setItem`例外の模擬では「書込み前に例外」か「書込みの成否不明」かを明記する。成否不明なら安全側の`unverified`とし、元データ不変を断言しない。

## 5. テスト追加と実装ゲート

- E3-09: `setItem`成功→`getItem`例外。`unverified`、元データ不変とは主張しない。
- E3-10: E3-09後、再読込で要求した星を確認。再書込み・revision加算なしで`saved`。
