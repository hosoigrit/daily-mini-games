# Game #0007｜バランス再検算 v0.4（設計データのみ）

> この文書は**数値検算**であり、ゲーム本体のテスト・人間のプレイテストではない。

## 前提とv0.3差分

- 6週×5営業日・初期資金30・製造単価2・価格3/4/5・焼成上限12。
- 需要=`clamp(baseDemand + demandDelta - penalty,0,12)`、当日の客数予報=`delta=-2〜+2`の幅。
- 雨天のみ価格5のペナルティを**4→5**に変更。晴れ0/1/3、曇り0/2/4、雨0/2/5。
- シナリオの天気・基礎客数・変動は**v0.3と同一**。ルール識別子はrules-v3。

- 自作のDPで各日価格3/4/5、製造0〜min(12,floor(現金/2))の合法手を列挙して算出。
- 全6週でv0.3の理論最大値 **60/69/79/66/67/60** と閾値が不変であることを確認した。
- 90件の予報上限下限の整合と1,170件の単日取引算術組合せの不変条件を確認した。
- 本番は乱数を使わないため、既定の固定週は反復すると攻略を記憶できる。

## 解釈と課題

- 最大利益は**未来の需要変動まで知っている**完全情報下の上限。通常の初見プレイでは実現が難しい場合がある。
- ★3は上限の90%以上であり、週別の初見達成確率が同一であることは保証しない。W04〜W06の体感難度は特に要確認。
- W01最適経路は`4×6→3×3→5×5→4×3→5×8`、利益`12+3+15+6+24=60`を維持。
- UIの予報は「可能な客数の範囲」であり確率分布ではない。価格5の雨の日の予報はv0.3の予報より上限・下限が1人分少なくなる場合がある（clampの影響あり）。
- 価格3/4/5に各週少なくとも1日ずつ単日利益最適（同率可）の日が存在することも再確認する。
